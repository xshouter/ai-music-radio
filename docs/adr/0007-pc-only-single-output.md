# ADR-0007 · v1 只做 PC 单端：删除 OutputTarget 端口与多端设计

- **状态**：已接受，**取代 ADR-0002**，**撤回 ADR-0003**
- **日期**：2026-10-20
- **关联**：`docs/abstraction-layer.md` 第 2 / 3.4 / 5 / 8 / 9 / 10 节

## 背景

ADR-0002 与 ADR-0003 建立在一条**没有被确认的假设**上：这个电台会同时有 PC 和手机两个客户端。
既然有多个客户端，就需要 `OutputTarget` 端口（`local` / `lan` / `upnp`），还需要讨论多端同时出声要不要选主。

真实需求是：**只需要 PC 端，只服务作者一台机器。** 手机端从未被提出过。

这条假设本该在 grill 阶段被问掉（铁律 2），却直接以"`lan` 是真实的第二个实现"为名义写进了 ADR。
ADR-0002 里其实已经埋了退路（"冲刺结束时若 `lan` 没用过就删掉"），但更该先问的是：**`lan` 到底是谁要的。**

## 决策

**把多端的一切删掉**：

- 删除 `OutputTarget` 端口、`core/output/` 目录、`GET /api/devices`、UPnP 占位实现，以及对应的测试替身。
- 删除 `net.lanAccess` 设置项（ADR-0005 的 `PrefMap` 同步修订）。
- PC 端由**渲染进程直接播放** `<audio src="/api/audio/:songId">`；server 只绑 `127.0.0.1`。
- 新增 `POST /api/playback`：声音是在渲染进程里真正响的，所以"开始了 / 放完了 / 被跳过"由**渲染进程回报**，
  server 不猜。`PlayEvent`（taste 闭环与统计的来源）因此是事实而不是预测。

同时修正一处用词：UI 的两种形态（**宽窗大钟态 / 窄窗卡片态**）是同一个客户端的响应式两态，
不是两个客户端。这个词法从第一天起就在鼓励"多端"的想象。

## 后果

- **好处**：少一个端口、少一个目录、少一个接口、少一个设置项、少一行测试替身；没有选主、没有心跳、没有设备注册表。
  这正是第 9 节想要的形状——**没有第二个实现，就不加端口**。
- **代价**：原型 UI 里有 UPnP 输出设备选择器，我们**不复刻**它（`docs/references.md` 里已写明这是范围外声明）。
  另外 `POST /api/playback` 是这次删除带来的**新契约面**，MVP 必须实现，否则 `track_end` 触发链是断的。
- **重新打开的条件**：出现**第二个真实播放目标**时（例如有线音箱要走 UPnP，或真的要用手机当遥控）——
  那时**先做实现，再加端口**，并同时恢复 ADR-0002 的讨论。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 保留 `OutputTarget` 但只实现 `local` | 一个实现撑不起一个端口，违反第 9 节；将来真需要时再加不迟 |
| 保留 `lan` 当作"以后可能有用" | 这正是反例清单的第一条 |
| 让 server 按 `durationMs` 推算曲目结束时刻 | 推算出来的 `PlayEvent` 会污染 taste 与统计；跳播、暂停、缓冲都会让它失真 |

# ADR-0009 · v1 不做歌词：把歌词从契约里收敛掉

- **状态**：已接受，**债已还清**（删除在 [PR #15](https://github.com/xshouter/edgerunner/pull/15) 落地，2026-10-20）
- **日期**：2026-10-20
- **关联**：`docs/abstraction-layer.md` 第 3.3 / 5 节、`shared/ports.ts`（`MusicSource`）、`shared/api-types.ts`（`LyricResponse`）、`docs/requirements/ui-player.md`

## 背景

抽象层第 3.3 与第 5 节把歌词当成一等公民：`MusicSource.lyric()`、`GET /api/lyric/:songId`、`LyricResponse`，
`docs/requirements/ui-player.md` 里还专门写了「歌词自解析、不引第三方 LRC 库」这条假设。

但复刻目标本身就说明了问题：参考界面的重心是**口播**——DJ 念出来的串词逐句浮现、逐词高亮。
歌词是另一条独立的文本流，它带来的是三份持续成本：

- 契约面：一个端点 + 一个响应类型 + 一个 LRC 解析器 + 时轴对齐（逐行还是逐字符）。
- 版权面：歌词是受版权保护的文本，要随作品集公开分发（exe + 仓库），风险高于只播音频。
- 注意力面：这一层是**要经得起细节拷打**的地方，多一个没人看的功能，就多一处会被问「为什么这么写」的地方。

## 决策

**v1 不做歌词。** 歌词从契约里收敛掉，`shared/ports.ts` 的 `MusicSource` **不含** `lyric()`。

边界与顺序：

- **端口先收敛**：`shared/ports.ts` 是新文件、还没有消费方，所以直接按最终形态写，不留一个已知要删的方法。
- **其余的面分批删**：`GET /api/lyric/:songId`、`LyricResponse`、`Lyric`、`mock/` 的歌词路由、
  `renderer/` 的 LRC 解析与歌词 UI —— 这些**都有测试正依赖**（契约测试里有一条歌词断言，前端测试里有 LRC 解析）。
  现在集中删会让 CI 出现中间态变红，所以和「UI 按新需求重做」放进同一个 PR 一起处理。
- 直到那次删除落地前，`/api/lyric/:songId` 仍在运行，但已不在契约的意图内；`docs/abstraction-layer.md` 第 5 节已就地标注。

## 后果

- **好处**：少一个端点、少一个类型、少一个解析器、少一条版权风险线；UI 的空间还给口播与队列——
  这正是参考界面的形状。`docs/requirements/ui-player.md` 里关于歌词的假设与阻塞项（歌词放在哪）随之作废。
- **代价**：
  - 同曲的「在唱哪一句」这种细节没了。将来要做，是**重新加回端口**（第 9 节的顺序：先有需求，再加端口），
    而不是复活这次的残留。
  - 已经合并进 `main` 的 3.1 UI 里有歌词组件，在删除 PR 落地前它会指向一个「契约不再承诺」的端点。
    这是已知的、有时限的债，**还债时间点写在上面**（UI 重做 PR）。
- **重新打开的条件**：出现「必须边听边看词」的真实场景（例如做卡拉OK式的跟唱、或要按歌词做时间对齐的视觉）。
  那时先做需求 grill，并按第 9 节重新引入端口。

## 债务偿还记录（2026-10-20）

「后果」里写的那个「有时限的债」已经还清，还债点与当时写的一致：单独一个只做删除的 PR（`feat/drop-lyric`）。

删掉的面：

- 契约：`Lyric`、`LyricResponse`、`GET /api/lyric/:songId`
- mock：`LYRIC` fixture + 歌词路由
- 契约测试：把「返回 Lyric | null」这条**换成**了「端点已经不存在（404）」——
  删除也要有断言，否则它可能变成一个没人调、也没人拦的残留
- renderer：`api/lrc.ts`、`hooks/useRadio.ts` 里的取歌词 effect 与派生、`Transport` 的 props 与 JSX、两处 CSS、`tests/renderer/lrc.test.mjs`

当时担心的「一起删会让 CI 出现中间态变红」其实不成立：**先删契约与 mock、再删 renderer，一次跑通就没有中间态。**
把这个 PR 单独拆出来的真正理由是它应该能被单独读懂、单独回滚（铁律 1），不是 CI。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 保留端点、只是 UI 不显示 | 契约里留一个没人调、也没人验证的端点，是「看起来能做的事」——违反第 9 节反例清单 |
| 保留歌词但做成默认关闭的开关 | 开关本身就是成本：要测两种态、要维护两份文案，而收益是零 |
| 现在就一次删干净（含 mock / renderer / 测试） | 会让这一个 PR 同时改契约、mock、测试、UI 四层，无法单独读懂、单独回滚（违反铁律 1） |

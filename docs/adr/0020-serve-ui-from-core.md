# ADR-0020 · 打包后的 UI 由内核一起发（同源）

- **状态**：已接受
- **日期**：2026-10-20
- **关联**：`core/server.ts`、`docs/adr/0007-pc-only-single-output.md`、`docs/abstraction-layer.md`（第 5 节）、`docs/requirements/core-serving.md`

## 背景

开发期 UI 由 vite 发（`localhost:5173`），它把 `/api` `/tts` `/stream` 代理到后端 —— **同源**，所以
`renderer/` 不需要任何 CORS 知识（`client.ts` 的注释里写得很清楚：mock 不发 CORS 头，跨源会被浏览器挡掉）。

打包之后没有 vite 了，只剩两条路：

- `file://` 加载 `dist/index.html`（vite 的 `base: './'` 就是为它准备的）；
- 或者由内核顺手把 UI 发出去。

而 `file://` 页面去请求 `127.0.0.1` 上的 `/api/now`，是一次**跨源**请求，且这个源是 `null` ——
浏览器的 CORS 会直接把它挡掉。`<audio>` 与 `WebSocket` 不受影响，但所有 `/api/*` 都会失败。

## 决策

**内核顺手把 UI 发出去**：`createRadioServer({ uiDir })` 给了目录，`GET /`（以及相关静态路径）
就从那个目录发文件。UI 与 API 因此**同源**，浏览器的 CORS 规则根本不会被触发。

三条边界：

1. **只发 `uiDir` 以内的文件** —— 路径先 `decodeURIComponent`、再 `resolve` 规范化，然后必须仍以
   `uiDir + sep` 开头，否则不发（`..` / `..%2F` 都挡在门外）。
2. **只认 GET/HEAD**，且**只豁免静态路径的令牌**：`/api/*` 与 `/tts/*` 照旧一律要 `x-radio-token`。
   初始文档没法带自定义头 —— 令牌护的是数据面，不是"能不能看到我们自己的界面"。
3. **给了 `uiDir`，非数据面的路径就只有一种含义**：要一个静态文件。发不到就 `404`，
   不让它掉进令牌检查（那会给一个对页面请求毫无意义的 `401`）。

## 后果

- **好处**：
  - `renderer/` **一行不用改**就同时适应 mock / dev proxy / 打包后三种环境（它本来就只跟
    "自己所在的源"说话）—— 这是铁律 3 想要的形状。
  - 没有 CORS 配置、没有 `Origin: null` 例外、没有第二个端口、没有自定义协议。
  - 对外仍然只有一个进程、一份令牌规则。
- **代价**：
  - `core/server.ts` 多了一件"发静态文件"的活。它的定位本来是"翻译层，不持有状态" ——
    发文件不持有状态，所以不算破定位，但确实是**第二个职责**。
  - 打包时必须把 `renderer/dist` 与 exe 放对位置（`main/` 负责算这个路径）。
  - 这是**用内核的代码换前端的复杂度**。在"前端只走 HTTP（铁律 5）"的前提下，这笔换得划算。
- **重新打开的条件**：UI 需要跨源分发（例如将来把界面搬到浏览器里访问局域网后端）时，
  这条路不再适用 —— 那时该做的是正经的 CORS + 令牌换票（`client.ts` 里已记着这条 shortcut）。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 后端给 `Origin: null` 发 CORS 头 | 等于为 `file://`（以及一堆沙箱 iframe）开一个跨源读口；`x-radio-token` 又会带来预检，`OPTIONS` 还得单独豁免令牌 |
| `file://` + Electron `webSecurity: false` | 把整个渲染进程的安全模型关掉，只为解决一个"地址从哪来"的问题 —— 代价远大于收益 |
| 由 `main/` 再起一个静态服务（另一个端口） | 多一个端口、还多一次跨源（UI 在 A 端口、API 在 B 端口，照样 CORS），没解决任何问题 |
| 自定义 `app://` 协议 + 代理 `/api` | 要自己写一次代理，等于把同一个问题换个地方实现一遍 |
| 让 vite 在打包时把 base URL 烘进 bundle | 端口是运行时才知道的（不该占死一个固定端口），token 更不该被烘进 JS 文件 |

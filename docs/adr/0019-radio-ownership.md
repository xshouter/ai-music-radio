# ADR-0019 · 电台状态机的分工：状态一处、播放两种权威、坏了只降口播

- **状态**：已接受
- **日期**：2026-10-20
- **关联**：`core/radio.ts`、`core/server.ts`、`core/plan.ts`、`docs/requirements/core-serving.md`、`docs/adr/0010-playback-authority-and-favorites.md`、`docs/adr/0007-pc-only-single-output.md`

## 背景

4.1–4.4 各自产出了零件：存储（`Store`）、大脑（`ToolLoopBrain`）、音源（降级链）、嗓子（TTS 引擎）。
4.5 要把它们装成一台电台。装的过程中有四件事必须**先定下来**，否则后面每一处都会各自发明一套：

1. 状态放哪儿；
2. "一首歌放完了"由谁推进；
3. 没有 key / 某一句合不出来时，停到哪一档；
4. 日表的时段从哪儿来。

## 决策

### 1. 状态只在 `core/radio.ts`，`core/server.ts` 不持有状态

server 只做"把 HTTP/WS 翻译成对 radio 的调用"。它没有 `current`、没有 `queue`、没有 socket 之外的任何东西。
**好处**：状态机可以**脱离 HTTP 单测**（4.5 的测试就是这么做的：内存 SQLite + 假 fetch，一个端口都不开）。

### 2. 两种播放权威并存（ADR-0010 的延伸）

- **用户切歌 = 客户端权威**：客户端自己切，再 `POST /api/playback {event:'started'}` 报事实。服务端只记账。
- **一首歌自然放完 = 服务端权威**：客户端报 `{event:'ended'}`，**由服务端**决定下一首放什么
  （客户端不猜下一首该放什么 —— 那就是把编排逻辑复制一份到前端）。

队列**没到底**时服务端只走一格（`stepLocally`），**不问大脑、不花钱**；只有队列到底才 `think()` 换一批。
"谁是下一首"因此在两个权威之间各管一段，边界是"这首歌是放完的还是被换的"。

### 3. 缺 LLM key 只降口播，不降音乐；单句合成失败只丢那一句

- 没有 key：发 `NO_LLM_KEY` 事件 + 队列自己走。**电台照常放歌**。唯一例外是 `chat` → 503。
- 单句 TTS 失败：发 `TTS_FAILED` + 一条"有字没声"的兜底 `SpokenLine`，继续下一句。
- 理由：**整条口播消失比"有字没声"更糟**；而"因为一个 key 没填就不放歌"更像故障，不像产品。

### 4. 日表的三个时段写死在代码里，曲目尽力而为

时段（07:00–12:00 morning / 12:00–18:00 daytime / 18:00–02:00 late-night）是**产品的脾气**，
理由和 systemPrompt 一样：不是运维参数，不给它一个配置入口。某格推荐不到歌就留空数组，不把整个日表搞坏。

## 后果

- **好处**：
  - 状态机可单测；server 薄到只剩路由与令牌。
  - 用户不需要先填 key 才能看见"电台在工作" —— 星空、队列、时钟、播放都能跑起来。
  - 日表不依赖网络健康：源挂了也只是那几格空着。
- **代价**：
  - 服务端与客户端对"下一首"各有一半判断权，**契约里必须写清 `started` 的双重含义**（已写在第 5 节）。
  - 时段写死意味着改时段 = 改代码 + 发版。v1 接受：这是"一个人用的产品"，不是排班系统。
  - 兜底 `SpokenLine` 会让 UI 出现"有字没声"的一行，靠 `TTS_FAILED` 横幅解释，不假装音频在。
- **重新打开的条件**：出现第二个真实终端（智能手机 / 局域网音箱）→ 状态归属要重来（ADR-0007 已经被同一类问题绊过一次）。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| server 持有状态（`current` 放 server 的闭包里） | 状态机没法脱离 HTTP 测；而且"按路径分发的路由"会慢慢长出业务判断 |
| 客户端自己决定下一首，服务端只回"随便给一首" | 编排（什么时候换批、换几首、跳过什么）会复制一份到渲染进程，两份必然分叉 |
| 没有 key 就整体停播 / 直接报错 | 一个没填的设置项把整个产品变成白屏，违背抽象层第 6 节 |
| 单句合成失败就把整条口播丢掉 | 用户看到"什么都没说"比看到"说了但没声音"更难理解 |
| 日表时段走配置（prefs 加几个 key） | 凭空多一组没人会改的设置项；ADR-0005 说加设置项 = 改契约 |

# ADR-0008 · 口播 TTS 用 Fish Audio

- **状态**：已接受
- **日期**：2026-10-20
- **关联**：`docs/abstraction-layer.md` 第 3.2 / 6 节、`shared/ports.ts`（`TtsProvider`）、`docs/roadmap.md` 阶段 4.4

## 背景

口播是这个电台的一半：没有声音，DJ 就只剩文字，参考源里「会说话的电台」这件事就丢了。

抽象层第 3.2 节只定义了 `TtsProvider` 的**形状**，把「用谁的嗓子」留成了开放项。阶段 4.4 要落实现，但第一个实现必须先有名字，否则两处定不下来：Settings 页的「音色」一栏没有落点，口播的错误语义（第 6 节）也没法具体到「哪种失败会发生」。

约束：

- v1 只服务作者一台机器（ADR-0007），但交付物是**别人下载、填自己 key 就能用的 exe**（`docs/roadmap.md`）。
  所以音色不能绑死在只有一个免费额度的平台上，也不能绑死在某家的 SDK 上。
- 说话必须在用户点下去之后**很快出声**，所以要求低延迟、能整段返回。
- TTS 属于「可失败的一环」（第 6 节的不变量）：**任何 TTS 失败都不许把音乐停掉**。

## 决策

**口播用 Fish Audio**（`https://api.fish.audio/v1/tts`），通过 `TtsProvider` 端口接入，不在业务代码里直接调用。

边界：

- 音色走 `reference_id`（Fish Audio 的 voice id），从 Settings 的 `tts.voice` 读；默认值在 4.4 落地时按英文口播挑一个。
- **一次请求 = 一句**，不是一整段。ADR-0001 已经把 `Show.say` 定成逐句数组，逐句合成天然对齐；
  这同时绕开了远端接口的单次文本长度上限。
- 缓存键含 `providerId`（第 3.2 节），落 `cache/tts/<hash>.mp3`，命中直接给文件，不再打远端。
- 失败（超时 / 限流 / 额度用尽）一律走第 6 节：退避重试 1 次 → 仍失败则**跳过这句口播、继续放歌**。

## 后果

- **好处**：音色质量足够撑住「电台感」，`TtsProvider` 是端口，将来换火山 / 百炼只需要加一个文件，
  `core/tts.ts` 与 UI 一行不动。逐句合成 + 内容寻址缓存让重复口播零成本。
- **代价**：
  - 它是**付费**服务，且国内直连需要 `HTTPS_PROXY`。这意味着「代理没配对」会成为一类常见故障，
    必须进错误文案（第 6 节的 `TTS_FAILED`），否则用户只会看到口播静默消失。
  - 远端有单次文本长度上限。现在靠「一次一句」绕开；将来若要合成整段（连续口播、长串词），
    必须先在 `core/tts.ts` 里切句。
  - 默认音色面向英文场景。v1 口播语言是英文（`docs/references.md`），所以先不处理中文音色；
    真要中文口播时只需换 `reference_id`，端口不动。
- **重新打开的条件**：Fish Audio 涨价到不可接受或连续不可用；或出现**必须离线**的场景
  ——那时加一个本地 TTS 实现，端口不变，只多一个文件。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 火山引擎 / 百炼 CosyVoice | 都能用，但各自要接 SDK 的签名与音色管理。没有第二个真实实现之前，先选接起来最短、音色最像人的那个；要换时端口已经在了 |
| 浏览器 Web Speech API | 零成本，但音色像导航播报，且 Chromium 的可用嗓音依赖系统，做不了 exe 的稳定基线 |
| 自建 / 自训练克隆声音 | v1 没必要，且引入训练链路与声音版权问题；Fish Audio 本身已提供克隆 |
| 一次做两个 provider 实现 | 违反第 9 节：没有第二个真实需求，就先不做第二个实现 |

# ADR-0018 · 媒体走 302 直连远端，不做反向代理

- **状态**：已接受
- **日期**：2026-10-20
- **关联**：`docs/abstraction-layer.md`（第 5 节媒体路径）、`core/server.ts`、`core/music/index.ts`、`docs/adr/0016-music-crypto-boundary.md`

## 背景

契约里有两条媒体路径，它们和 `/api/*` 的其它端点不一样：**调用方是 `<audio>` 元素**。

- `/api/audio/:songId?level=` —— 要把一首歌的音频交出去；
- `/tts/<hash>.mp3` —— 要把一句口播的字节交出去。

音乐源（网易云兼容服务）给出的是一段**远端 CDN 的 URL**。问题：服务端要不要把这字节自己拉下来再转发？

## 决策

**不转发**。`/api/audio/:songId` 直接 `302` 到远端 URL。

口播那条相反：`/tts/<hash>.mp3` **由我们自己给字节** —— 因为那些字节是**我们自己生成的**（4.4 的内容寻址缓存），
它没有远端 URL 可指。这条要支持 `Range` / `206` / `416`。

另外，这两条路径都**豁免 `x-radio-token`**：`<audio>` 设不了自定义请求头。

## 后果

- **好处**：
  - 远端 CDN 认 `Range`、认分片、认断点续传，**中间过一手只会把播放器搞坏** —— 拖进度条会变成整段重下。
  - 服务端不占带宽、不占内存，不用管"拉到一半客户端跑了"这种半途状态。
  - 音频的真相留在音乐源那一侧（`expiresAt` 也是它管），内核不新增一个音频缓存层。
- **代价**：
  - 前端的请求直接打到远端 CDN，**同源策略与 CORS 由远端决定**。封面 CORS 已经在阶段 3 反复踩过，
    音频这一层如果有同样的问题，解决办法也要在前端那一侧（不能用 `crossOrigin` 时就走降级封面）。
  - 如果远端返回的是个**临时 URL**（带过期的签名），302 之后短时间失效是远端的正常行为，
    重试路径就是再打一次 `/api/audio/:songId`。
- **重新打开的条件**：需要离线缓存整首歌时（4.4 明确不做音乐离线缓存），或需要把音频改做成防盗链时。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 服务端拉下来再流式转发 | 为了一个"看起来更聚合"的架构，把 `Range` 支持、内存占用、半途中断全揽到内核里 |
| 服务端拉下来缓存成文件再给 | 音频是**版权内容**且体积大；本项目的缓存只覆盖口播（ADR-0009 / core-tts 需求假设 3） |
| 把远端 URL 塞进 `/api/now` 让前端直接播 | 等于把"歌在哪里"这一份真相搬到前端（铁律 5 的精神）；而且 URL 会过期，前端没法重试 |

# ADR-0004 · taste 不再回写 markdown，结构化存储 + 视图渲染

- **状态**：已接受
- **日期**：2026-10-20
- **关联**：`docs/abstraction-layer.md` 第 3.6 节；开放问题 4

## 背景

v0.1 里 `TasteRepo.appendLearned(line, evidence)` 会往 `taste.md` 追加文本。三个问题：

1. **格式漂移** —— 不同轮次写出的句子结构不一样，文件越来越不像人写的。
2. **无限膨胀** —— 追加只增不减，几百条之后这个文件没人会读。
3. **互相覆盖** —— 并发写同一个文件。

更根本的是：**人写的语料**和**系统学到的结论**混在同一个文件里，人就不再敢改它了。

## 决策

**分清地盘**：

- **人写的语料**（4 份 md）—— 人的地盘，**只读**，系统永不修改。
- **系统学到的** —— 系统的地盘，以结构化 `TasteUpdate { ts, text, evidence }` 存 SQLite。

`GET /api/taste` 同时返回两者（`TasteDoc` = 语料原文 + 最近若干条更新）。**系统不再回写任何 md。**

## 后果

- **好处**：格式稳定、可查询、单条可删可回滚；人写的文件永远被动不到。
- **代价**：少了"打开一个文件看全 taste"的便利——改由 Profile 页提供这个视图。
- **重新打开的条件**：如果发现人希望把系统学到的结论**固化**进语料，就加一个"提升为语料"的动作——写进 md 的是人主动的动作，而不是系统的自动追加。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 继续追加 markdown | 漂移 / 膨胀 / 覆盖，三个问题一个都没解决 |
| 全部结构化，人写的语料也进库 | 人不再能直接编辑自己的口味语料，得不偿失 |

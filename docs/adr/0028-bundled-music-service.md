# ADR-0028 · 内核代管兼容服务的启动，但不当它的实现

- **状态**：已接受
- **日期**：2026-10-20
- **关联**：ADR-0016（本条改它最后一条前提）、ADR-0023、`docs/requirements/bundled-service.md`、
  `docs/journal/2026-10-20.md` 第 37 条

## 背景

ADR-0016 把网易云的加密层隔离在一个「兼容服务」里、`core/` 只当 HTTP 客户端 —— 这条今天仍然成立。
但它附带的那句前提不成立了：**「这个服务由使用者自己准备」**。

第 36 条的实测给出了代价：服务不在时，大脑拿不到任何合法曲目 id，`emit_show` 全驳回，
于是**音乐和口播一起哑掉**。用户拿到的不是「降级」，是「装完没反应」。
对一个「下载 exe 就能用」的交付物（ADR-0023），这不是能留给 README 一句说明的差距。

## 决策

**内核代管启动，但不管实现。** `main/netease-service.ts` 在电台启动时把内置的一份
`NeteaseCloudMusicApi` 拉起来，把 `baseUrl` 交给 `startRadio`；退出时收掉它。边界：

- **`core/` 一个字不动。** 它拿到的仍然只是一个 `baseUrl`，仍然只当 HTTP 客户端。
- **不复用 3000。** 每次 `listen(0)` 向操作系统要一个空闲端口 —— 本机 3000 上很可能坐着用户自己的那一份，
  抢它就是把「谁在服务」变成不确定。
- **`EDGERUNNER_NETEASE_BASE_URL` 优先级最高。** 给了就用外部的、不 spawn —— 开发与复测靠它。
- **拉不起来不是错误。** 退到本地源，原因照旧由 `MUSIC_SOURCE_UNREACHABLE` 挂到界面上。

## 后果

- **好处**：「下载 exe → 只填两样（LLM apikey、网易云 cookie）」这条闭环了，用户不必再去起第二个进程。
- **好处**：换实现仍然只是换一个目录 / 一个 `baseUrl` —— ADR-0016 的可替换性没被削弱。
- **代价**：发布物从 ≈169MB 涨到 ≈196MB（内置 27MB，含它自己的传递依赖）。
- **代价**：**硬杀进程会留下孤儿。** 正常路径（`before-quit`）会 `stop()`，但 taskkill / 崩溃时那份服务会留在内存。
  它不占我们的端口（每次启动都挑新的），所以挡不住下一次启动，只是白占内存。
  要根治得上 Job Object 之类的父进程绑定，v1 不做。
- **代价**：冷启动多一段等待（服务要先生成 `anonymous_token`），就绪探测的上限给了 20s。
- **重新打开的条件**：出现「用户明确要接自己的音乐源实现」时，把 `EDGERUNNER_NETEASE_BASE_URL`
  从开发后门升格成界面上的开关；那时顺带决定内置那份要不要允许被关掉，以省下这 27MB。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 把 `NeteaseCloudMusicApi` 写进 `dependencies` | 它不是被 import 的库，而是**要被 spawn 的进程**；写进去等于把它那一大串传递依赖混进根 `node_modules`，打包时反而要逐个点名。按目录装、按目录拷，边界最清楚（和 `vendor/piper` 同一套路） |
| 直接占 3000 | 用户自己可能已经在 3000 上跑着同一份服务；抢它会让「谁在服务」不可知，而且失败时两边都说不清 |
| 要求用户装 Node | 发布物里已经有 Electron，它自带 node（`ELECTRON_RUN_AS_NODE`）。多要一个运行时是白要的 |
| 把加密实现抄进 `core/music/` | ADR-0016 已经否决过一次，理由不变：那是会烂的东西，一次上游变更就要动内核 |
| 起不来时弹窗 / 自动重启 | 既有降级链已经能演到「只剩本地音乐 + 一条说明原因」；多一层重启只会让「起不来」更难查 |

# ADR-0012 · 一句口播自带音频与词时间戳（`SpokenLine`）

- **状态**：已接受
- **日期**：2026-10-20
- **关联**：PR #18 · `docs/requirements/ui-onair.md`（3.8 需求）、`shared/domain.ts`、`shared/api-types.ts`、
  `docs/abstraction-layer.md` 第 5 节、ADR-0001（Show 逐句推）、ADR-0008（TTS 用 Fish Audio）

## 背景

3.8 的口播全屏态要两件契约里还没有位置的东西：

- **逐词高亮跟随音频**：UI 要知道这一句里每个词落在音频的哪一段，否则只能整句一起变色。
- **口播进度**：UI 要知道这一句（这一段）有多长，才能算「播了多少 / 总共多少」。

原来的 `say` 载荷是 `{ index, line }`（ADR-0001 定的「逐句推」）。它只够把文字一句一句浮现，
不够放音频，也不够放时间戳。而时间戳**必须与音频同源**：真 TTS（ADR-0008）返回的 word-level
时间戳是相对它自己那段音频的；UI 要是自己估一个时长，TTS 一接上就会「词走完了声音还在放」——
这正是这类界面最容易露馅的地方。

## 决策

`say` 的载荷从 `{ index, line }` 扩成 `SpokenLine`：

```
SpokenLine { index; line; audioUrl; words: SpokenWord[] }
SpokenWord { text; startMs; endMs }
```

边界：

- `words[].startMs / endMs` 是**相对这一句音频起点**的毫秒；一句的总长 = 末词的 `endMs`。
- `audioUrl` 指向**这一句**的音频（真后端 `/tts/<hash>.mp3`；mock 是同形状的内存静音 WAV）。
- 契约**只加字段、不加事件类型**：`say` 仍然逐句推，`StreamEvent` 的成员集合没变。
- v1 的两个实现（mock / 阶段 4 的 Fish Audio）都必须给出词时间戳；给不出时退化成「一个覆盖全句的词」，
  形状不变，UI 自动变成整句高亮。

## 后果

- **好处**：
  - UI 只读一份真相（后端给的词区间），不自己猜时长；阶段 4 换真 TTS 时前端一行不改。
  - 进度条与高亮同源，不会对不上。
  - mock 能造出与真 TTS 同形的载荷，3.8 的界面在阶段 4 之前就能验收，并被契约测试钉住。
- **代价**：`say` 的载荷变大（每句带一份词表）。逐句推本来就是为「一句一句合成」（ADR-0001），
  这份词表随句子一起到达，节奏不变。
- **重新打开的条件**：真 TTS 只能给句级时间戳时 —— 退化成整句高亮，契约形状不变，只改 provider。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| UI 按字符数估时长 | 与音频不同源；TTS 一接上就「词走完音频还在放」 |
| 新增逐词事件 `say-word` | 事件数量爆炸（一句十几个帧），且破坏 ADR-0001 的「逐句推」节奏 |
| 词表只挂 `DjMessage.meta`，不动 `say` | `meta` 是 `Record<string, unknown>`，能塞但**没有类型**；词时间戳是跨端契约，必须被契约测试约束 |
| 前端自己调 TTS 拿时间戳 | 违反铁律 5（前端不碰 provider / 不碰 key）；TTS 是付费调用，必须服务端缓存（阶段 4.4） |

> 备注：UI 侧仍然用 `DjMessage.meta.turns` 把逐句到达的 `SpokenLine` 攒成一段，好让「点开全屏」
> 一次拿到整段。那是 UI 的汇总，不是契约。

> **追记（2026-10-20，见 ADR-0017）**：落地 4.4 时核实了 Fish Audio 的接口 —— 它**不给**词级时间戳。
> 所以这里写的"给不出时退化成「一个覆盖全句的词」"不是例外而是常态。改成从**音频真时长**推（总长真实、逐词按比例切），
> 只有总长都拿不到时才退化成整句一个词。形状（`words[]`）不变。

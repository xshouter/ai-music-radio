# ADR-0036 · 设置页不许说谎：模型目录随端点读，嗓子选了却没钥匙就等于没选

- **状态**：已接受
- **日期**：2026-10-21
- **关联**：`core/radio.ts`（`ttsProviderFor` / `models()`）、`core/server.ts`、`shared/api-types.ts`、
  `mock/server.mjs`、`renderer/src/components/Credentials.tsx`、`renderer/src/api/client.ts`；
  ADR-0005、ADR-0008、ADR-0011、ADR-0022、ADR-0025、ADR-0027、ADR-0034
- **需求**：`docs/requirements/voice-models-player.md`

## 背景

用户实测 0.1.7 之后提的三条，其实是同一件事：**设置页上写的东西，和电台实际会做的事，不是一回事。**

**① 「放歌的时候没有口播」的一半。** `ttsProviderFor` 当时的判据只有一个条件：

    if (prefs['tts.provider'] === 'fish') -> FishTts

它只看**选了什么**，不看**有没有钥匙**。选了 fish 而 `tts.apiKey` 是空的，这条路会一直往
`http://127.0.0.1:8080/v1/tts` 打、一直失败。用户看到的是「有字没声」，
而他永远等不到远端的那一声。

**② 模型名要手打。** `llm.model` 是一格自由文本。拼错一个字母，报出来的是上游的 400/404 ——
从界面上那行字看不出是自己手滑。而端点自己就知道它认识哪些模型（OpenAI 兼容的 `GET /models`）。

**③ 不在本决策里的一条。** 「真的走了读曲库 -> 生成 taste.md 的流程吗」的答案是「没走」，
但那是 ADR-0025 那个决策的**触发点选错了**，属于实现缺陷：改法是换触发点，
不需要新开一个决策跟 ADR-0025 打架。见「后果」一节。

## 决策

**① 嗓子：选了 HTTP 的 TTS 却没有 key，等于没选。**

判据改成 `tts.provider === 'fish' && tts.apiKey !== ''`。不成立就落到 piper —— 离线、零 key、
随包就在。为什么不报一个错让用户去填：那会把一台**本来能出声**的电台变成一台哑电台，
而哑的原因是「你没配一个可选的配置项」。

**② 模型目录随端点读，做成一个可打可挑的框。**

新契约：`POST /api/models { baseUrl: string; apiKey?: string } -> { models: string[] }`。

- 服务端打 `GET {baseUrl}/models`，取 `data[].id`，去重、排序。
- `apiKey` 缺省用库里存的那把；**现填的那把优先** —— 用户填完 key 还没保存就该看见下拉框。
- 明文只用一趟：不落库、不落日志（ADR-0035 的请求头禁令在 `main/` 那一层已经覆盖这条出网）。
- 失败走 `llmFailureCode`（ADR-0027）：401/403 是 `NO_LLM_KEY`，429 是 `RATE_LIMITED`，
  别的 5xx 是 `INTERNAL`。**界面把它当「列表拉不到」处理，不挂横幅** —— 下拉框是方便，不是门槛。
- 界面用 `<datalist>` 而不是 `<select>`：既是下拉框，也能手打。

**③ 音色那一格从界面上删掉。**

界面不该把「随包的那把嗓子」说成一件要配置的事。TTS 块只剩 PROVIDER 一个 `<select>`；
选 piper 时给一句话说明它随包、离线、不用填；选 fish 才问端点与钥匙。换音色仍是
`tools/fetch-voice.mjs` 的事（ADR-0022）。

## 后果

- **好处**：设置页上「填了」= 「生效了」；`llm.model` 不再靠背；选了没配的嗓子不再是哑的。
- **代价**：多一个 HTTP 端点、多一次出网。那一次只在「设置页打开 + 端点 + 钥匙齐了」时发，
  而且是停手 600ms 才发（边打字边发是白花请求）。口径上它是一次**读**：不改任何状态。
- **顺手把 ADR-0025 的触发点修了**（不新开决策）：`learnTaste()` 原来只在「cookie 从无到有」
  那一刻跑，于是早就填过 cookie 的人**永远**得不到 `taste.md`。改成 `boot()` 里排表之前先补一次、
  `saveSettings` 里无条件补一次（已有一份时读一眼文件名就回来）。ADR-0025 的决策本身
  （读曲库 -> 写画像 -> 落 md）一个字没改，改的是**什么时候去问它**。
- **重新打开的条件**：出现「模型目录要缓存」「要给每个模型标上下文长度 / 价格」
  「要看 `/models` 之外的能力探测」—— 任何一条都说明一个裸的字符串数组不够用了。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 选 fish 而没 key 时报错让用户去填 | 把「你没配一个可选的配置项」变成一台哑电台。落 piper 当场就有声音 |
| 启动时就把 `/models` 读一遍缓存起来 | 端点可以随时换；缓存意味着用户改了 baseUrl 还看见旧列表 |
| 用 `<select>` 替换那格输入 | 把「端点没列出来但确实能用」的模型锁死。`<datalist>` 两样都给 |
| 顺手校验 model 在不在列表里，不在就拦下 | 列表是建议不是白名单（代理端点、私有部署都会漏）。拦下来只会多一条走不通的路 |
| 把 `POST /api/models` 并进 `GET /api/settings` | 后者是纯读、无出网、无参数；前者要打远端、要 baseUrl、可能失败。并进去等于让「打开设置」变成一件会超时的事 |
| 为模型下拉引一个 UI 库（combobox 组件） | 原生 `<datalist>` 就够，而这一页的视觉是手画的（`.cred-field` 那一套），引库要重做样式对齐 |

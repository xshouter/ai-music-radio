# ADR-0002 · `OutputTarget` 在 v1 保留，且有两个真实实现

- **状态**：已接受
- **日期**：2026-10-20
- **关联**：`docs/abstraction-layer.md` 第 3.4 / 9 节；开放问题 2

## 背景

反例清单写着："为了'以后可能有用'提前加端口"是禁止的——端口必须有**第二个真实实现或明确的迁移计划**。
而 v1 里 `local`（Electron 窗口内的 `<audio>`）看起来是唯一的真实输出。那这个端口是不是空转？

## 决策

**保留端口，而且它不空转**：

- `local` —— Electron 窗口内播放。
- `lan` —— 手机/其他浏览器打开 `http://<host>:<port>`，自己从 `/api/audio/:songId` 取流自己播。**这是第二个真实实现，不是假想。**
- `upnp` —— 只注册一个抛 `not implemented` 的实现，UI 里以禁用态出现（样式待参考截图，铁律 4）。

`GET /api/devices` 的 DTO 只含 `{ id, kind, label, available }`；`play` / `stop` 不出现在响应里。

## 后果

- **好处**：手机端不需要另建通道就能听；将来接 UPnP 只是加一个实现。
- **代价**：v1 多写一层注册表与设备列表。如果 `lan` 在两天冲刺里实际没用上，这层就是多余的。
- **重新打开的条件**：冲刺结束时若 `lan` 从未被真实使用过，v1.1 把 `lan` 与 `upnp` 一起删掉、只留 `local`，并同步删掉这个端口。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| v1 先不建端口，UI 里直接 `<audio>` | "声音往哪儿出"这件事会散在 UI 里，将来接 UPnP 要改 UI |
| 当场造一个假的第二实现来凑数 | 凑数不解决任何问题，还会掩盖"这个缝是不是切错了" |

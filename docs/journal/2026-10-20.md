## 困难 1 · 私人笔记已经躺进公开仓库

**发生了什么**：仓库创建后 `visibility` 是 `PUBLIC`，而 `main` 里带着一份私人笔记 `参考源.md`。
它链向本地知识库的其他笔记（简历准备、另一个项目 nanobot），等于连私人目录结构一起公开了。
发现时它已公开约一天。

**为什么会发生**：建仓库时默认选了 public，**在第一次 push 之前没有清点"这个仓库里到底装了什么"**。
一个只服务作者自己的项目，"公开"这件事本身就没有被当成一次需要评审的变更。

**代价（说清楚，不遮掩）**：旧提交 `6397c5c` 在 GitHub 侧仍可能被按 SHA 访问，直到平台回收不可达对象为止。
强推只能保证它不再出现在任何分支的历史里，不能保证它立刻从平台上消失。

**怎么处理**：
- 改写 root commit，把 `参考源.md` 从历史里彻底移除（`6397c5c` → `10142af`），强推 `main`。
- 重建分支提交（`0290953` → `a7340a0`），保证 PR 的 diff 只包含该有的文件。
- 私人笔记的**公开替代品**写成 `docs/references.md`：只保留公开可说的部分（原型链接、行为观察），
  去掉一切本地路径与内部链接。

**沉淀成规则**：项目文档一律按"要给陌生人看"的尺度写；私人笔记永不入库。

## 困难 2 · 强推基线把 PR 弄坏了

**发生了什么**：为了让 PR 的历史干净，先强推了 `main`（基线），再强推分支。
结果 GitHub 把 PR 钉在旧的 head SHA 上，`mergeable` 一直是 `UNKNOWN`，重开也失败
（`Could not open the pull request`），只能关掉旧 PR 另开一个（PR #2）。

**教训**：改写历史的操作顺序应当是——**先改写远端基线，再让 PR 在干净基线上重新生成**；
更要紧的是：如果一个仓库有开着的 PR，就别在它脚下动基线。
这也是「历史里不该有私人文件」这件事必须**在第一个 PR 之前**处理掉的原因。

## 困难 5 · 第一次 CI 跑了 4 分钟才被领走

**发生了什么**：workflow 文件推上去之后，`gh run list` 一直是空的——GitHub 没有为那次 push 生成任何 run。
补一个空提交重新触发，run 才出现，但 `queued` 持续了约 4 分钟才被 runner 领走（同一账号后续的 run 只需 7 秒）。

**当时的判断**：这是新账号首次注册 workflow 的冷启动，不是配置错误。为了不让它卡住地基合并，
先在本地用故障注入证明脚本会红，然后合并；等 CI 真的跑绿之后才开分支保护，避免 PR 卡在"等待状态检查"。

**沉淀成经验**：新增 workflow 的 PR，第一次 push 未必触发 run——**要显式再推一次来确认它被识别**，别假定它在跑。

### 困难 1 · 契约测试抓出的第一个真 bug：mock 会把上一轮的口播推给新客户端

WS 测试要求「连上先拿到 now/queue/plan 快照，之后 chat 的 `say` 逐句推」。第一次跑，`says[0].index`
是 2 而不是 0。根因不在测试：`speak()` 用的是全局 `broadcast`，而 `say` 是靠 `setTimeout` 一句一句推的；
**上一个测试触发的 chat 还剩两句没推完，新客户端正好在这期间连上来，于是收到了一段它从没点过的口播。**
改成「只发给这一轮开始时已在线的客户端」。这正是契约测试该干的事：把一条时间上的耦合逼出来。

### 困难 2 · 测试进程挂住不退

同一个测试的另一半：断言一失败，`socket.destroy()` 就没被执行到，socket 泄漏，

教训：**测试里开的长连接，销毁要放在「失败也会执行」的地方。**

### 困难 4 · 未知路由该回哪个错误码

契约里的错误码是**封闭枚举**，里面没有 `NOT_FOUND`。所以未知路由只能借用 `INTERNAL`，
但 HTTP 状态码仍该如实回 404。第一版让 `sendError` 直接用错误码自带的 500，测试立刻抓到。
已在 `sendError` 上加 `status` 覆盖位。

### 困难 5 · 本机工具链的绕路（环境注记）

`apply_patch` 走不通——命令经 `cmd` 传递时会在第一个换行处被截断，多行补丁传不过去；`Remove-Item` 被策略直接拦下。
最后的路子是：写文件用 PowerShell 的**单引号 here-string** 配 `[IO.File]::WriteAllText` + `UTF8Encoding($false)`（无 BOM）；
删临时文件用 `node` 的 `fs.rmSync`；读文件用 `node` 打印（node 的 stdout 是 UTF-8，中文正确；PowerShell 的 stdout 不是）。

### 困难 6 · `node --test <目录>` 在本机和 CI 的 Node 之间不是一个东西

本地 `node --test tests/`（Node v26）把 `tests/` 当目录递归找测试文件，14 条全绿；
CI 上同一个命令（Node v22）把它当**模块路径**解析，直接 `Cannot find module .../tests`，8 秒就红。
在本地怎么跑都复现不出来——只有把命令真的交给 CI 才会暴露。
改成 `node --test`（不给路径），让 test runner 自己按约定发现 `*.test.mjs`，两边行为一致。

**沉淀成规则**：`npm test` 里的命令必须是**在 CI 的 Node 版本上也成立**的命令，本机跑绿不算证据——
尤其是「把路径交给工具」这种跨版本语义变过的地方（`node --test`、`tsc --build`、各种 glob）。

### 困难 7 · 字体许可文件在最后一步被本机网络掐断

**发生了什么**：抓字体的脚本一路成功（两个 woff2 + CSS + NOTICE 全落盘），最后一步去 `cdn.jsdelivr.net` 取 `OFL.txt` 时 `ECONNREFUSED`。
本机 hosts 把 github.com 指到 127.0.0.1、还挂着加速器，外部域名的可达性是抖的——同一个 URL 前一分钟还是 200。

**为什么难**：脚本是「一次跑完」的写法，90% 的产物已经落盘，只差两个文件；重跑没用，因为失败是随机的。

**怎么处理**：把「字体本体」和「许可文本」拆成两件事——本体走 `fonts.googleapis.com`（可达），
许可文本走 `raw.githubusercontent.com`；后者证书链被中间人换过（`UNABLE_TO_VERIFY_LEAF_SIGNATURE`），
于是这次一次性抓取里关掉证书校验（抓的是公开许可文本，这个取舍可接受）。
最后把 `NOTICE.md` 里的版权行和两个 `OFL.txt` 的实际内容逐字核对过。

**沉淀**：抓取脚本要**幂等且分段**——一步失败不该让前面 90% 白干。

### 困难 11 · 降级时界面说的和后端说的不是同一首歌

**发生了什么**：切到降级后，后端把 `now` 换成 `l9001`（本地兜底曲，**根本不在队列里**），

**根因**：取值写的是 `current = queue[cursor] ?? now.track` —— 队列被当成了权威，后端只是备选。

**怎么修**：取值顺序改成「本地刚跳过的 → 后端 `now` → 队列位置」，并且一收到 `now` 事件就清掉本地选择。

**沉淀**：「后端是权威」不是写在文档里的一句话，是要落到**取值顺序**上的。

### 困难 13 · 测试先抓到我，而不是抓到代码

## 深夜 · Player 重做成 616×876 单态（PR #16）

3.5 还完歌词的债，3.6 才真动布局：把「响应式两态」换成「一块固定画布 + 等比缩放」。
基准尺寸 **616×876** 不是目测的：参考源口播卡片的 CSS 里写着
`.card { width: 616px; height: min(876px, calc(100vh - 48px)); border-radius: 28px }`。
顺带记一个发现：`mmguo.dev/claudio-fm/` 那一页是**落地页**，卡片是它自己的 demo（`#fmCard`），
里面的歌名、口播、时间都是营销用的假数据。所以复刻它复刻的是**壳**，数据模型一行都不许从它那儿抄。

### 困难一：scale 只能算在 JS 里，而且它会把 fixed 坐标系统也换掉

CSS 的 `scale()` 只吃无单位数，而 `min(100vw/616, 100vh/876)` 算出来是长度（长度除以数还是长度），
塞不进 `transform`。所以缩放比例只能在 JS 里算一次、写到 `--scale`，CSS 只负责吃这个变量。
`resize` 监听是唯一的副作用 —— 这一处不许再长出第二处。

第二个坑更隐蔽：`transform` 会给子元素建立新的包含块，`position: fixed` 从此不再对窗口定位，
而是对着这块画布。**所以 DJ 详情弹层写在 `.stage` 里面，不是挂在 body 下** —— 否则它在缩放后
会飘到画布外面去。这不是随手放的，是被 `transform` 逼出来的位置。

### 困难二：配色不能靠眼睛，也不能靠抽帧

参考源截图是有损压缩，视频抽帧更靠不住（这条教训 journal 早记过）。这次直接读像素：

- light 模式的强调色采样出 `#2ffdb4` —— 和 dark 的 `#29FFB8` 是同一个绿，于是**两态同值**，
  不必为浅色主题调暗它。
- 浅色模式下圆形运输键区域最深只有 `#565656`：参考在浅底上**没有**沿用深色实心圆键，
  而是换成描边灰。所以 `--btn` 在 light 里是 `transparent`，只有发送键保持深色。
- dark 模式下 `HIDE` / `FAV` / `LOGIN` 的描边原来取 `--line`（`#232327`），压在 `#101013` 的
  面板上几乎看不见。这个在代码里读一百遍也发现不了，是把截图并排看才发现的 —— 补了 `--pill-line`。

### 困难三：曲目卡挂不上去（真 bug，值得记）

第一版我赌「POST 比 WS 的 `say` 先回来」，把 `pendingTracks` 写在 POST 的 `.then()` 里，
等 WS 建新消息时套上去。**赌反了**：mock 的 `speak()` 第一句只等 120ms，而经过 vite proxy 的
POST 更慢，于是卡片永远挂不上 —— 界面看着「没坏」，功能就是不出现。

改法是不赌顺序：`say()` 先记住「我这条消息的 id」；POST 回来后把 `{ after, tracks }` 放进 ref，
再调 `withCards()` 去找「我这条之后的第一条 DJ 口播」挂上；WS 的 `say` 建新消息时也调同一个函数。
`withCards()` 靠「已经有卡片就不动」保证幂等，所以两条路径谁先到都对。

教训：**跨两条通道（HTTP + WS）拼同一条 UI 状态时，任何「谁先谁后」的假设都要写成两条路径。**

### 决策

| 决定 | 为什么 |
|---|---|
| 曲目卡挂在 `DjMessage.meta.tracks` | `meta` 本来就是 `Record<string, unknown>`，不动 `shared/api-types.ts` 就不需要开 ADR（铁律 3） |
| 基准 616×876 是量出来的 | 参考源卡片的 CSS 真值 + 用户答复同一个数；我只负责把它当唯一画布 |
| CSS 里再也搜不到 media query | 单态的定义就是这个：一个 DOM、一套布局，折的只是尺寸不是结构 |
| `HIDE` / `LIST` 是 QUEUE 区的折叠开关 | 需求 3.6 里定的；参考里是同一个按钮的两个标签 |
| `♡` 与 `FAV` 本轮只上形状 | 一个 PR 只做一件事；它们对应 3.7 的双来源切换 |

## 深夜后半 · QUEUE 双来源与行内删除（PR #17）

3.6 把两个按钮做成了死按钮（`♡` 上挂着 `title="Favorites arrive in 3.7"`）。3.7 把它们接上，
顺手把 QUEUE 变成「同一块面板、两份列表」。

### 困难一：`display: none` 的按钮点不着（真 bug，键盘用户复现）

第一版 `✕` 是 `display: none`，`:hover` / `:focus-within` 时改成 `display: grid`。
鼠标看着完全正确 —— 悬停出现、点一下删掉。**但键盘用户永远碰不到它**：
`display: none` 的元素不能被聚焦，所以 `:focus-within` 永远不会成立，这个循环是自锁的。

测试方法也值得记：headless 里没法悬停，本来打算跳过这条验证（「纯 CSS，看着对就行」）。
改主意是因为发现**聚焦可以让同一组 CSS 生效** —— `:focus-within` 和 `:hover` 写在同一个规则里。
于是 `document.querySelector(".q-row .x").focus()` 一把就把它证伪了：`display` 还是 `none`。
改法是 `opacity: 0` + `pointer-events: none`：藏起来了，但**仍然可聚焦**。

教训：**「纯 CSS 的视觉改动」也要找一条能从脚本触发的等价路径去验，`focus` 常常就是那条路。**

### 困难二：切换来源会把正在播的歌重载

`localPick` 只在 AI 队列里找。在 FAV 源点一首播着，再切回 AI 源 → 解析不到 → `current` 落回
`now.track` → `currentId` 变 → `<audio>` 的 effect 重跑 → 那首歌被中途重载。
这不是「界面不对」，是**声音会断**。改成两份列表都找就没了。

### 困难三：按下的胶囊看不见

`.pill` 从来没有 `[aria-pressed='true']` 的样式（`aria-pressed` 是 3.6 加的，样式没人跟），
所以 `FAV` 按下去毫无反馈 —— 而它恰恰是这一轮唯一的开关。补了实心样式之后发现 `HIDE` 也被点亮，
可参考里那枚一直是描边；于是把 `HIDE` / `LIST` 的 `aria-pressed` 拿掉：它的状态已经由文案表达，
不需要第二个信号。

### 决策

| 决定 | 为什么 |
|---|---|
| `FAV` 按下会**顺带打开面板** | 开关就该带你去看见它打开了什么 |
| `source` 留在 `useRadio` 里 | 它决定 `move()` 走哪份列表，不是纯展示 |

| `✕` 用字符而不是新图标 | 规格已定：这套界面的符号语言是字符（`♡ ■ ↑ ▸ ★`） |

### 困难 1：`key` 撞车，整棵口播子树被反复追加

`<OnAir key={oral.seq} …>` 的 key 是**裸数字** `1`。它和同一层里 `{cond && <X/>}` 这种兄弟节点的
**隐式下标 key** 撞上（`false`/`null` 也占一个位置），React 报 two children with the same key，
于是每次重渲染都把 `.onair` 又追加一份——DOM 里堆到 11 个。

修法：key 加前缀 `'oral-' + oral.seq`，不再和兄弟节点的数字 key 相撞。

### 困难 2：长口播被 `scrollIntoView({block:'end'})` 挤成空框

对齐可视区底部」，等于把正文顶到看不见——截图里那条 DJ 消息是一片空白。
改成按高度选：`last.offsetHeight <= list.clientHeight ? 'end' : 'start'`（够高就从顶上读）。

## 3.9 凭证弹窗（PR #19）

Profile 是 `plan` 的唯一去处（交互决策 8），同时要装下收听统计与口播 / 聊天历史。三块数据里只有一块在契约里有出口
（`GET /api/taste`，加上 `GET /api/plan/today`）；另外两块在 `shared/ports.ts` 里**有端口方法**
（`Store.playStats` / `Store.recentMessages`），却从来没有 HTTP 出口 —— UI 拿得到「现在播什么」，
拿不到「我这些天听了什么」。

于是开 ADR-0013：只加两个**只读**端点，形状直接等于既有端口方法的返回类型（`PlayStats` / `DjMessage[]`），
不新增 DTO、不加写端点。阶段 4 接真后端时这两个方法是现成的，不需要新表。

### 困难：mock 以前不记账

`POST /api/playback` 在 mock 里一直是空实现（`await readJson(req)` 之后回 `{ ok: true }`）。
以前没有任何出口读它，所以没人发现。现在统计要读，就必须让 mock 真的记 —— 否则 Profile 上的数字永远是 0，
那一版界面等于没验。这类「假后端假装成功」的坑不会自己暴露，**只有第二个消费者出现时才会现形**。

顺手把两个易踩的边界钉进契约测试：`limit` 越界要**夹住**而不是报错（错误码是封闭枚举，里面没有
「参数不合法」这种码）；`history` 必须**倒序**，不许让 UI 自己排。

### 一个静默的坑：`Number(null) === 0`

第一版 `historyPage` 写成 `Number(limitRaw)`，而 `searchParams.get()` 在参数缺失时返回 `null` ——
`Number(null)` 是 `0`，于是「不给 limit」变成「limit = 1」，历史只剩一条。改成先判 `null` / `''` 再 `Number()`。
这类错不抛异常，只静默地少几条数据，最难发现。

### 验证

typecheck / boundaries（renderer 15 个文件）/ `npm test` 27/27（新增 2 条）/ build 通过。截图在 3.11 一起出。

## 3.11 Profile（PR #21）

### 做了什么

`Profile.tsx`：DjCard 的下一级 —— 那边回答「你是谁」，这边回答「你听了什么、taste 长什么样」。
四块：TASTE（语料 + 学到的）、TODAY（日表）、STATS（播放 / 跳过 / 重播 + Top 艺人）、HISTORY（最近消息）。
入口是 DjCard 页脚新加的 `PROFILE →`；`client.ts` 加 `getStats` / `getHistory` 两个取值函数。

### 困难 1：浅色主题里强调绿当文字用，几乎看不见

采样到的 `#2ffdb4` 是**填充**色。白底上做小字，对比度约 1.3:1 —— 等于看不见：
`TASTE` / `TODAY` / `STATS` / `HISTORY` 四个小标题、`MORNING` / `DAYTIME` / `LATE-NIGHT` 三个 mood 全是浅绿。

修法不是逐个改，而是分清「填充色」与「文字色」：新增 `--accent-ink`（深色态 = `--accent` 本身，
浅色态 = `#07724f`，对白底约 5.8:1），把 styles.css 里 27 处 `color:` / `border-color:` 换成它，
只剩 6 处 `background` / `box-shadow` 继续用亮绿。深色态一个像素没变（两个 token 同值）。

**这一条值得记**：「换主题」不是把同一个值抄两遍，而是要问这个值承担什么角色。
3.9 的凭证弹窗没发现，是因为浅色态里强调色只出现在很小的 `SET` 徽标上，没被注意。

### 困难 2：Doto 又在 12px 上糊了

时间戳第一版用 `--dot`（Doto）。点阵字体在 12px 下每个点被抗锯齿糊成虚线，读数变成猜数（主界面小标签踩过同一个坑）。
时间戳改用 `--label`（Space Grotesk）+ `tabular-nums`；STATS 的三个数字改用与 DJ 详情同款的人话粗体。

### 困难 3：空态不能「想当然」

「三块各自有空态」写进验收标准很容易，验它却要真把数据清空 —— 而 mock 里数据永远是满的。
给 `/__mock/control` 加了 `{"wipe":true}`（**不在契约里**，UI 永远不调它，与 degraded / error 同一个规矩），
一次清空两本账 + 语料 + 日表，截图确认五个空态各自出现。空态这种东西只有真看过才算做过。

### 决策

- 打开 Profile 就关掉 DjCard：弹层永远只有一层，`Esc` 不会一次关两个。
- 四份数据用 `allSettled` 并发拉：一块坏了另外三块照常显示，错误在页脚报一次；
  未回来时该块显示 `—`，拉回来但为空才显示空态文案 —— 「没有数据」和「还没到」要分得开。

### 验证

四件套全绿（typecheck / boundaries 16 个文件 / `npm test` 27/27 / build）。截图：
`27-dark-profile`、`28-dark-profile-history`（滚到底）、`29-light-profile`、`30-dark-profile-empty`。

## 3.12 · 按钮文字的可读性（PR #22，插队补丁）

### 做了什么

用户复看后仍说「按钮上的文字看不清」。这一轮不猜，先把「真的是渐隐吗」证伪：
用 CDP 在页面里遍历全部 `<button>` 及其所有祖先，把 `mask-image` / `-webkit-mask-image` /
`opacity !== 1` / `filter !== none` 全打出来 —— **一条都没有**（只有 `.send:disabled` 的 0.4）。
所以「渐隐」是观感，不是效果：按钮小字用的是 `--text-dim`（`#8a8a90`），浅色底上约 3.1:1，
在 9–10px 上看着就是糊的。

修法：把**按钮 / 控件**的小字从 `--text-dim` 换成已有的 `--btn-text`（深色 `#acacac`、浅色 `#565656`，
对各自底色都在 7:1 以上），共 7 处：`.pill` / `.seg button` / `.vol` / `.banner .dismiss` / `.ghost` /
`.cred-btn` / `.q-row .x`。没有新增 token —— `--btn-text` 本来就是干这个的。
非按钮的层级灰（`QUEUE`、`3 TRACKS`、时间戳、`statusbar`）保持不动：层级要留得住。

### 困难 1：同一句反馈，两轮才找到根因

第一轮（PR #18）我把它判成**字体**问题（小标签原来写 `var(--dot)`），换成 Space Grotesk 就算交付了。
用户复看还是说看不清 —— 说明当时的「修好了」是自以为的。教训：把反馈修到「我认为对」，
不如先把它证伪一次。这次花 5 分钟写探针，比再猜一轮便宜。

### 困难 2：Doto 在 15px 以下一律糊

同一批小字里还剩几个 Doto：头像里的 `E`（13px / 11px）、feed 头部 `EdgeRunner`（15px）、
口播右上角时钟（15px）。点阵字体到 15px 以下，每个点被抗锯齿吃掉，读起来像虚线 —— 这是「渐隐」观感的另一半来源。
Doto 只留给**大字**（wordmark 27px、大钟 88px、`dj-name` 36px、`oa-name` 32px、`dj-face` 24px），
其余 4 处改回 `--label`。参考源自己也只在 wordmark 与大钟上用点阵，这不算走样。

### 决策

- 不新增 token：`--btn-text` 的语义本来就是「按钮上的字」。
- 不整体调亮 `--text-dim`：它是**层级**用的灰；调亮会让 `QUEUE` / `3 TRACKS` / 时间戳抢正文。只动按钮。

四件套全绿（typecheck / boundaries 16 文件 / `npm test` 27/27 / build）。截图 `t3-main-dark` /
`t3-main-light`（口播两态逐像素一致 —— 「口播不跟主题变」这条本轮又审了一遍，没有回退）、

## 4.1 · Store：SQLite + 内存替身（PR #23）

### 做了什么

- **契约面**：`shared/ports.ts` 的 `Store` 去掉泛型 `getPref<T>`，换成封闭 key 映射 ——
  ADR-0005 从"纸面决策"变成"编译器看得见的东西"。
- `core/state/migrations/0001_init.ts`：六张表（messages / plays / favorites / prefs / plans / taste_updates）。
- `core/state/sqlite-store.ts`：`Store` 的真实现；`core/state/memory-store.ts`：零依赖内存替身。
- `tests/core/store.test.mjs`：**同一串操作打两个实现**，断言快照逐字段一致。
- `core/tsconfig.json`：把 `core/` 纳入 `npm run typecheck`（此前只编译 `shared/`）。

### 困难 1 · 用哪个 SQLite：一个原生模块会把分发路堵死

抽象层原话是 better-sqlite3。它是**原生模块**：Electron 里要 `electron-rebuild` 重编 ABI，
交叉编译进 Windows exe 尤其脆。而本项目的分发模型是"别人下载 exe → 填自己的 key"，
一个装不上的原生依赖等于把这条路直接堵死。Node 22.5 起自带 `node:sqlite`，正好是零依赖的那一档。

但真正的问题不是"选哪个库"，而是**谁拥有这个依赖**。于是决定：`core/` 只声明它要的最小结构接口
（`exec` + `prepare` + `run/get/all`），驱动由唯一组装点 `main/bootstrap.ts` 注入。
这条写成 [ADR-0014](../adr/0014-core-driver-injection.md)。

### 困难 2 · CI 是 Node 22，本机是 Node 26

`node:sqlite` 在 22 上要 `--experimental-sqlite`，本地（26）不用。这是最经典的一类分叉：
**本地绿、CI 红**，而理由藏在 "实验性 API 什么时候摘掉 flag" 这种没人记得住的细节里。
把 CI 提到 24（那里不需要 flag）。注意：`--experimental-strip-types` 两边都还在用，
`npm test` 因此能直接跑 `.ts`。

### 困难 3 · 迁移为什么不是 `.sql` 文件

打包成 exe 时 `core/` 会被打成单文件，运行期没有 `migrations/*.sql` 可读 ——
一个"为了 SQL 好看"的选择换一个运行期故障不划算。SQL 以 `String.raw` 字符串住在 `.ts` 里，
目录形状与版本号都不变。

### 困难 4 · 跨实现一致性测试抓到一个真 bug

`node:sqlite` 返回的行是 **null 原型对象**，而 `deepStrictEqual` 会连原型一起比 ——
`playStats().topArtists` 直接把驱动行往上传，两个实现立刻被判成不同。
修法是 store 自己造普通对象。这正是"单测一个实现只能证明它自洽"的实例：
如果不是拿两个实现对着跑，这个 `[Object: null prototype]` 会一路漂到 server 的 JSON 里，
而 JSON.stringify 会把它抹平 —— 于是没有任何一处会报错，只是契约悄悄变脏。

### 困难 5 · 记账语义必须逐条对齐 mock

`Store` 上没有"重播"这个入参（`PlayEvent` 里没有 `replay`），但 `PlayStats.replays` 要有数。
定法：**replay 在写入时算**（同一首已有记录就是重播），两个实现与 mock 三条线同一个定义。
收尾（`endedAt !== null`）时找**最近一条**还没收尾的同曲记录；找不到就丢弃 ——
重复上报不该凭空造一条播放记录。
时间戳相同时"越晚插入越靠前"也必须两边一致，否则 `recentMessages(2)` 的断言会随机漂。

### 决策

- `replay` **不进** `domain.PlayEvent`：它是**记账的产物**，不是播放事实。让 Store 自己算。
- 越界夹住、非法回默认（`clampLimit`）：错误码是封闭枚举，里面没有"参数不合法"这种码（ADR-0013）。
- 设置项坏在库里（例如 `llm.protocol = 'gemini'`）→ 回默认值 + 记一条警告，**不抛错**：
  不能因为一个设置项坏了就让电台起不来（ADR-0005）。

### 验证

四件套全绿：typecheck（`shared` + `core` + `renderer`）/ boundaries（renderer 16 + core 5 + shared 3 个文件）/
`npm test` **31/31**（原 27 + 新增 4）/ build。
## 4.2 · 大脑：自建 tool loop + 两个 provider（PR #24）

### 做了什么

- `core/providers/http.ts`：provider 需要的**全部** HTTP 能力（POST / 状态码 / 文本），可注入。
- `core/providers/llm-openai.ts` + `core/providers/llm-anthropic.ts`：两个兼容面。
- `core/prompt.ts`：人设 + 上下文（语料 / 最近播放 / 日表 / 天气）组装。
- `core/brain/index.ts`：`ToolLoopBrain` —— 四个工具、`emit_show` 唯一出口、最后一步强制定稿。
- `tests/core/brain.test.mjs`：9 条。
- `tools/smoke-llm.mjs`（`npm run smoke:llm`）：真 key 的手工冒烟，一条命令跑完一整轮推理。

### 困难 1 · 三套工具写法，两个文件里抹平

同一件事在两家的写法完全不同：OpenAI 的 `tool_calls[].function.arguments` 是 **JSON 字符串**
（不是对象），工具结果走独立的 `role: 'tool'` + `tool_call_id`；
Anthropic 的 `tool_use.input` 是**对象**，工具结果伪装成**一条 user 消息**里的 `tool_result` 块，
而且 `max_tokens` 是**必填**。
这三处就是"加第三个厂商＝加一个文件"的代价清单 —— 好在这份清单不会更长。

### 困难 2 · Anthropic 只认 user / assistant 两种角色

连续两条工具结果必须**合并进一条** user 消息；分开写会得到两条连续的 user 消息，上游直接 400。
`toAnthropicMessages()` 里那段"看上一个元素是不是纯 tool_result"就是干这个的，测试里专门钉了一条。

### 困难 3 · "每个 tool_call 都要有回音"

OpenAI 面要求 assistant 的**每一个** tool_call 后面都必须跟着对应的 tool 消息，少一条直接 400。
第一版里"驳回 `emit_show`"只回了拒绝理由，没回同一条回答里其它 tool_call 的结果 ——
**这是测试数消息数时发现的**，不是线上发现的。

### 困难 4 · 测试自己先错了三回

新增 9 条里第一次跑红 4 条，**全部是我对契约的误读，不是实现的错**：
- 以为"工具抛错"之后模型随手 emit 就能过 —— 忘了 id 必须来自**本轮**的 registry（工具挂了就没有候选，这一轮就该定不了稿）。
- 以为可以直接写一条"已收尾"的播放记录 —— `Store` 只认"收尾一条已开启的记录"，直接塞会被丢掉。
- 以为 `maxSteps` 用满 6 步只会有 2 次请求。

测试红了是好事：它证明那几条校验**真的在拦**。校准期望比校准实现便宜得多。

### 困难 5 · 拿不到真 key 的诚实交代

用户点名要给的百炼 key，落盘文件 `apikey.txt` 是 **0 字节**；仓库里的 `.env.local` 只有 `NCM_COOKIE`。
所以这一 PR **没有真 key 的冒烟证据**，只有脚本化 provider 的协议级证据（9 条测试全绿）。
为此专门写了 `tools/smoke-llm.mjs`：填上 key 后一条命令就能端到端验一轮（含工具轨迹与最终 Show），
而且它**永不打印 key**。这条差距写在 PR 正文里，不含糊过去。

### 决策

- 工具集合**封闭**（4 个）；`emit_show` 是**唯一**出口；最后一步强制 `tool_choice = emit_show`（ADR-0015）。
- 校验是**硬**的：id 必须来自本轮工具返回值、`reason` 必须有、`say` 不能空。
- 驳回时把**具体理由**当 tool 结果送回模型 —— 这是自愈的唯一入口。
- 工具失败是**结果**不是崩溃：交回错误，让它换工具、换说法。
- 人设与说话规矩写进代码，**不做成配置**：它是产品的一部分，不是运维参数。

### 验证

四件套全绿 + `tests/core/brain.test.mjs` 9/9。
真 key 冒烟：**未做**（困难 5），命令已备好 —— `npm run smoke:llm`。
## 4.3 · 音乐源与降级链（PR #25）

### 做了什么

- `core/http.ts`：把 HTTP 抽到 core 级并支持 GET（原来 `core/providers/http.ts` 只够 POST）。
  **它是个工具，不是某个 provider 的私产** —— `core/music/` 也要用它，而 provider 层必须是叶子。
- `core/music/netease.ts`：网易云客户端（字段映射 + 日推两级退让 + 单档 resolve）。
- `core/music/local.ts`：本地目录兜底源。
- `core/music/index.ts`：`MusicSourceChain` —— "档位 × 源"的笛卡尔积降级。
- `tests/core/music.test.mjs`：6 条，零联网。

### 困难 1 · 网易云的加密层放哪儿

这是本 PR 真正的分叉点。web 接口要过 `weapi` 的 AES + RSA。
抄进 `core/` 意味着**把会烂的东西放进内核**：密钥、算法、反爬对策，一次上游变更就要动核心，
而且它和我们自己的抽象没有任何关系。决定：加密层由一个**兼容服务**承担，`core/` 只是个 HTTP 客户端。
代价要诚实说：v1 的"下载 exe 就能跑"在**音乐源这一环上不闭环** ——
没有兼容服务 / 没有 cookie 时，电台退到本地目录继续工作。这条写进了 ADR-0016 与 README。

### 困难 2 · "日推"听不懂"慢一点"

`/recommend/songs` 是**账号**级推荐，它给的是"你会喜欢什么"，不是"今晚想听什么"。
所以 `recommend` 被拆成两条路：**有场景词走搜索，没有才走日推**。
这条直接决定了大厨能不能真的接住"something quiet"这种话。

### 困难 3 · 一次 HTTP 抽象写窄了

4.2 里 `HttpFetch(url, init)` 只够 POST —— 网易云的接口几乎全是 GET + query。
这次把它改成 `HttpFetch(request)`（url 在请求对象里，method 是 `'GET' | 'POST'`），
顺手把 `LlmHttpError` 改名 `HttpError`：错误不是 LLM 专属的。

### 困难 4 · "本地文件是什么音质"

一开始想让本地源"声称低一档"，好让 UI 的档位看起来一致。
想清楚之后否掉了：本地文件没有档位可言，声称低档就是**让 UI 显示错的东西**。
改成照请求的那一档回 —— 观测到的就应该是真的。

### 困难 5 · 又是我的测试先错了

"按文件名排序"那条断言我按自己的直觉写成了 `Untitled` 在前，实际是 `M < U`。
小错，但和 4.2 是同一个模式：**先校准期望，再校准实现**。

### 验证

链的换源与笛卡尔积降级 / 本地兜底与"目录不存在只是没歌"）。全程零联网。
## 4.4 · 口播合成与缓存（PR #26）

### 做了什么

- `core/tts.ts`：**内容寻址缓存**（键 = sha1(providerId + 音色 + 文本)，落 `cache/tts/<hash>.mp3`）
  + 失败重试 1 次 + **从音频真时长推词时间戳**；失败抛 `TtsFailure`（`code: TTS_FAILED`）。
- `core/providers/tts-fish.ts`：Fish Audio 叶子（`POST /v1/tts`，`format: mp3`，音色走 `reference_id`）。
- `tests/core/tts.test.mjs`：6 条，零联网。
- 顺手把 mock 的 `tts.provider` 出厂值从 `dashscope` 对齐成 `fish` —— 它跟 `DEFAULT_PREFS` 说的不是同一个东西。

### 困难 1 · ADR-0012 的兜底其实是常态

写 4.4 前先核实了 Fish Audio 的**真接口**：`/v1/tts` 直接回 mp3 字节，响应里没有任何对齐字段。
也就是说，ADR-0012 里那句"给不出时退化成『一个覆盖全句的词』"**不是例外而是每天都会走的路**。
照字面执行 = 这个界面的逐词高亮永远只是个摆设。
决定：**让词时间戳从音频本身推** —— 总长（读 mp3 帧头，不解码）是真的，逐词按文本长度比例切。
这条偏离写进了 ADR-0017，并在 ADR-0012 末尾补了追记。

### 困难 2 · 差半拍的高亮，要不要？

比例分配出来的逐词边界**不是口型对齐**，英文长短词混排时会差半拍。
纠结过要不要干脆不做，只给整句高亮（= 严格照 ADR-0012）。
想清楚之后留下来了，但把话说死：这是"看起来对"的高亮，不是"逐帧对"的高亮，代价写在 ADR-0017 里，不装作它是精确的。
换来的是进度条总长与音频**同源** —— ADR-0012 最担心的"词走完了声音还在放"不会发生。

### 困难 3 · 缓存放哪儿：文件还是 SQLite？

4.1 刚刚把数据库驱动做成"core/ 不认识、main/ 注入"（ADR-0014），很容易一顺手把音频也塞进 SQLite 的 BLOB。
没这么做：ADR-0008 已经写了 `cache/tts/<hash>.mp3`，而且 `core/music/local.ts` 早就直接用 `node:fs` 了 ——
文件系统是平台，不是需要被抽象掉的外部依赖。音频是运行时数据，`cache/` 早就在 `.gitignore` 里。
少一个端口、少一层注入，测试用临时目录就够。

### 决策与取舍

- provider 永远是叶子：缓存、重试、时间戳都在 `core/tts.ts`，`TtsProvider` 只管一次调用（ADR-0008 的边界）。
- 重试**只一次**：付费接口 + 用户在旁边等，两次是上限；再失败就跳掉这句、继续放歌（抽象层第 6 节）。
- `wordsFor` 做成**纯函数**并导出：不碰网络、不碰 fs，能单独测。

### 困难 1 · 小目录永远是空的（`degraded` 恒为 false）

我一开始把"从工具结果里捡完整 Track"写成希望工具回一个**裸数组**。写测试时才看清：
`emit_show` 的 id 校验要求"只能用本轮工具真的返回过的 id"，而工具结果里放的是 `remember()` 处理过的
**TrackRef**（只有 id/title/artist）—— `source` 在这条路上被丢掉了。

后果不只是"少一个字段"：`NowPlaying.degraded` 是**推断**出来的（队列里每一首的源都是 local 才算降级），
目录空 = 推断恒为假 = UI 上的 DEGRADED 徽标永远不会亮，`plays.source` 也永远记 `unknown`。
改法：让 `remember()` 保留**整条 Track**，只在交给 UI 的地方（`emit_show` 的 `play`）窄化成 `TrackRef` ——
**契约一个字段没变**，变的是"内核内部有没有把 source 带出来"。
代价诚实说：工具结果现在会多带 album / coverUrl / durationMs，模型多看到几个用不上的字段。

### 困难 2 · 不带参数的 `/api/stats` 会 500

`stats(since)` 原本是"先 `new Date(NaN)`，再造今天零点"。`setHours` 修不好一个 Invalid Date ——
`new Date(NaN)` 上 setHours 之后仍然是 NaN，一路带到 `store.playStats()` 里的 `since.toISOString()`，抛 `RangeError`。
也就是说 `GET /api/stats`（不带参数，最常用的那个）是坏的。改成 `new Date(clock.now())` 再 setHours。

这条是**写着测试才发现的**。只写实现不写测试，它会一直坏到用户点开 PROFILE 的那一刻 ——
而这正是"端到端测试"比"单元测试"多买到的那一点。

### 决策与取舍

- **ADR-0018**：媒体走 302 直连远端，不反向代理（远端 CDN 认 Range，中间过一手会把播放器搞坏）；
  口播字节相反 —— 那是我们自己生成的，没有远端 URL 可指，所以由我们给字节并支持 Range/206/416。
- **ADR-0019**：状态只在 `radio`、`server` 无状态；用户切歌 = 客户端权威、一首自然放完 = 服务端权威；
  缺 key 只降口播不降音乐；单句合成失败只丢那一句；日表的时段写死。
- 队列没到底时**只走一格、不问大脑** —— 这是"别为了队列里已经有的东西再花一次钱"。

## 5.0 · 打包后的 UI 与 API 同源（PR #29）

### 做了什么

- `core/server.ts`：新增可选的 `uiDir` —— 给了它，`GET /` 就从那个目录发 UI（`serveUi`，约 30 行）。
- `tests/core/ui-serving.test.mjs`：3 条（发文件 / 越界一个字节都不给 / 没给 uiDir 时 `/` 没有路由）。
- ADR-0020：为什么打包后由内核发 UI，以及被否决的四条路。

### 困难 1 · 打包之后"跨源"这件事才冒出来

开发期 UI 由 vite 发并代理 `/api`，所以是**同源**，`renderer/` 一行 CORS 逻辑都没有 —— 也正因如此，
这件事在阶段 3–4 从来没被碰到。打包后只剩 `file://`：它的源是 `null`，于是所有 `/api/*` 的请求
都会被浏览器的 CORS 挡住（`<audio>` 与 `WebSocket` 不受影响，所以只有数据面会挂）。

想过四条路：给 `Origin: null` 发 CORS 头 / `webSecurity: false` / 由 `main/` 再起一个静态服务 /
自定义 `app://` 协议。四条要么在开安全口子，要么只是把同一个问题换了个地方实现。
最后选"内核顺手把 UI 发出去"：**同一个端口、同一个源**，CORS 规则根本不会被触发，
而 `renderer/` 依然一行不用改（它本来就只跟"自己所在的源"说话）。

### 困难 2 · 越界检查必须放在 resolve **之后**

`/../secret.txt`、`/..%2Fsecret.txt` 这类路径要挡住。第一版我先做字符串检查再拼路径 —— 那是错的：
`..` 的规范化发生在 `resolve` 里，字符串阶段的"看起来没越界"并不说明 `resolve` 之后也没越界。
改成：先 `decodeURIComponent`，再 `resolve(uiDir, path)`，**然后**要求结果仍以 `uiDir + sep` 开头。
测试也刻意用原始 HTTP 请求发路径 —— `fetch` 会把 `../` 规范化掉，用它测等于在测客户端。

### 决策与取舍

- **ADR-0020**：UI 由内核发，同源。代价是 `core/server.ts` 多了第二个职责（发静态文件）；
  换到的是前端零 CORS 知识、零多余端口、零自定义协议。
- 令牌只豁免**静态路径**：初始文档没法带自定义头，而令牌护的是数据面，不是"能不能看到界面"。
- 给了 `uiDir` 之后，非数据面的路径只有一种含义（静态文件），发不到就 `404` ——
  不让它掉进令牌检查，因为对一个页面请求来说 `401` 毫无意义。

### 验证

- `tests/core/ui-serving.test.mjs` **3/3**；四件套全绿。
- 反例验证：`/../secret.txt`、`/..%2Fsecret.txt`、`/assets/..%2F..%2Fsecret.txt` 三条越界路径
  全部 `404` 且响应体里**不含** uiDir 外面的文件内容。

## 4.6 · 语料仓库（PR #30）

### 做了什么

- `core/taste.ts`：抽象层第 3.6 节的 `TasteRepo`，之前只有构造参数、没有实现。
  `read()` 一半读磁盘（目录里的 `.md` = 语料）、一半读库（`recent` = 系统的结论）；
  `appendLearned()` 只落库，永不回写 md。
- 曲风胶囊从 `genres.txt` 读 —— 曲风是**数据**不是装饰（ADR-0010）。
- `docs/requirements/core-taste.md`：语料在磁盘、结论在库（ADR-0004）的落地说明。

### 困难 1 · 语料到底是谁的地盘

最省事的做法是让系统把"学到的"追加进 `likes.md`，一份文件既能人写又能机写。否掉了：
一旦系统回写，人的手写原文就和机器生成的行混在一起，下次 `read()` 读到的就不再是"人写的东西"。
ADR-0004 的取舍是**物理隔离**：语料是 md（人的地盘），结论是库的一行（系统的地盘）。
代价是 `read()` 要读两个地方；换到的是"人写的东西永远是人写的"。

### 困难 2 · `appendLearned` 失败要不要弄砸 `♡`

`♡` 在 `radio.feedback()` 里做两件事：`store.setFavorite()` 落库、`taste.appendLearned()` 记一笔学到的。
后者失败绝不能让前者回滚 —— 用户点的是喜欢，喜欢已经记住了，"学到"只是账外的一笔。
所以那一句 `.catch(() => {})`：学不会不报错，也不影响接口返回。

### 困难 3 · 顺序得稳定，否则 UI 每次刷新都换位

`readdirSync` 的顺序不保证。语料按文件名 `localeCompare` 排一遍再发，Profile 里的语料顺序才稳定。
空文件剔除、单份 2000 字截断、最多 12 份 —— 都是"别把整个目录糊到 prompt 里"的上限。

### 决策与取舍

- **目录不存在 = 没有语料**，不是错误。冷启动 `readdirSync` 抛错当空目录，UI 显示空态而不是报错。
- **时间戳走注入的 `clock`**，不 `Date.now()` —— 可测，和内核其它地方一致。
- 测试里 `learned` 是异步 push 的，断言前必须先跑完 `feedback` 的响应 —— 修了一次测试的解构（漏了 `learned`）。

### 验证

- `tests/core/taste.test.mjs` **3/3**；`tests/core/radio.test.mjs` **8/8**（含"♡ / 取消 ♡ 各落一条学到的"）。
- 四件套全绿。

## 5.1 · Electron 外壳（PR #31）

`/api/*` 要 `x-radio-token`，可初始文档与 `<audio>` 设不了自定义头。走 `webPreferences.additionalArguments`
把令牌喂给 preload，preload 写成 `window.__RADIO__`。渲染进程那边只加了一条兜底 —— 没动任何业务逻辑。
（WS 仍然不带令牌，靠"只监听 127.0.0.1"兜底，见 `client.ts` 里的 shortcut 注释。）

结论：GDI 截图抓不到 Chromium 的 GPU 合成层（老问题），不是代码问题。**验证手段本身会骗人，得换一个证据源。**

- `README.md` 重写：下载 → 填 key/cookie → 网易云兼容服务 → 数据在哪 → 开发命令 → 出包流程 → 诚实边界。

### 困难 1 · 怎么保证"装出来的包"和"我本地验过的"是同一条路

第一反应是让 CI 跑 `ubuntu-latest`（便宜、快）。否掉了：本地是 Windows，电子包在 Linux 上打 NSIS 要多一层 wine ——
那是一类"只在 CI 上坏"的差异，正是这个项目最怕的东西（4.1 的 Node 22/24 分叉已经吃过一次）。
改成 `windows-latest`：贵一点，但走的是同一条从没人走过的路被替换成了有人走过的路。

### 困难 2 · 出包前要不要再跑一遍门禁

要。Release 是"这一刻的树是绿的"的声明，不能只信 PR 时的绿。workflow 里 boundaries / typecheck / test / build
再跑一遍；任何一步红，就没有安装包 —— 宁可没有 Release，也不要一个说不清状态的 Release。

### 决策与取舍

- **draft 而不是直接发**：tag 推上来先落草稿，人看过再 `gh release edit <tag> --draft=false`。
  多一步，换到"发出去的东西是被人看过的"。
- **不引入自动化版本号**（semantic-release 之类）：v1 只有作者一个人发版，一个 tag 足够；
  多一个工具就多一处会坏的东西。

### 验证

- `release.yml` 语法与步骤按本地跑过的那条链逐条对齐（本地 `npm run dist` 已产出 106.6 MB 的
  `EdgeRunner-0.1.0-setup.exe`，`resources/app.asar` 里只有 3 个文件、无凭证）。
- 流水线本身要等真打 tag 才会被执行 —— 这一点如实写在 PR 里：**已本地验证，未在 CI 上跑过 tag**。
- 四件套全绿。

## 5.3 · 发布这一步自己来（PR #34）

### 做了什么

- `.github/workflows/release.yml`：`--publish never` 出包 → 用 `gh release create` / `gh release upload` 自己发布。
- `electron-builder.yml`：删掉 `publish` 配置，并写明为什么删。
- 只上传安装包本身，不传 `latest.yml` / `.blockmap`。

### 困难 1 · 一个 tag 建出了两个 draft Release

5.2 合并后推 `v0.1.0`，流水线**成功**，但 Release 列表里出现**两个**同 tag 的草稿：
一个只挂了 `.blockmap`，另一个挂了 `.exe` + `latest.yml`。资产散在两个草稿里 ——
对"点进去下 exe"的人来说，这等于没有。

翻日志：`electron-builder` 在同一次运行里打了**两次** `publishing`（相隔 2ms）。
它自带的 GitHub publisher 在没有现成 release 时会各建各的。这个行为在别人的项目里也许被某个开关按住，
但与其去猜开关，不如**不把发布这件事交给它**。

### 困难 2 · 本地复核时 `release/` 被锁住

改完本地复跑 `--publish never`，卡在 `EBUSY: resource busy or locked, unlink ... app.asar` ——
上一轮跑起来的 Electron 进程还没完全退干净。这与本次改动无关（打包已经走到 packaging 这一步），
于是把真正的验证放到 CI 上：**重打 tag，看它是不是只出一个草稿、只挂一个 exe**。

### 决策与取舍

- **不传 `latest.yml` / `.blockmap`**：那是自动更新通道的元数据。这个应用**还没有更新器**，
  传上去等于对外宣称一条不存在的通道。等真做更新器时再传（那时先写 ADR）。
- **`gh release create` 写在 `||` 后面**：重跑流水线时草稿已存在，`gh release view` 成功就直接跳到上传；
  `--clobber` 让资产可覆盖。整条发布步骤因此是**幂等**的。
- **不换 GitHub Actions 的 release 动作**（softprops 之类）：`gh` 已经在用（PR 全走它），少一个第三方动作少一处会坏的东西。

### 验证

- 四件套全绿；`--publish never` 能被 electron-builder 接受（本地已进到 packaging 阶段）。
- **重打 `v0.1.0` 后**：Release 列表应只有一个草稿、只挂 `EdgeRunner-0.1.0-setup.exe`。结果见本 PR 的评论。

## 收尾审计 · 四处「文档说了、仓库没做」

交付前把目标逐条对着仓库核一遍（不是对着记忆），抓到四处**文档 != 事实**（前三条是「声称了一个没实现的机制」，第四条是「计划改了、描述没跟着改」）。都不是功能坏了，
而是**文档描述的东西和仓库里的东西对不上** —— 对这个作品集来说，这比功能坏掉更糟：它考的正是「细节经不经得起拷打」。

1. `docs/roadmap.md` 的 3.13 / 4.6 还写着「✅ 本 PR」，而 PR #27 / #30 早就合并了。
2. `docs/engineering-rules.md` 铁律 5 写着「机械检查（两道）」，第一道 ESLint（`no-restricted-imports` +
   `import/no-restricted-paths`）**在仓库里根本不存在**：没有 eslint 配置文件，`package.json` 里也没有 eslint。
   真正只有 `tools/check-boundaries.mjs` 这一道。
3. 抽象层第 7 节第 4 步、`docs/roadmap.md`、ADR-0006、阶段 2 需求、CI 注释，五处都写着
   「**同一组断言**同时打 mock 和真 server」。
4. 抽象层第 7 节还留着**设计期**的措辞：「Player 两态 + 歌词同步」、mock 是「一个 ~100 行的 Express」、
   歌词清理「由 UI 重做那个 PR 一并完成」。三条都已被后来的决定推翻（3.2 单态 / ADR-0009 去歌词 / mock 是零依赖 http），
   第 7 节却没跟着改。

### 困难 · 第 3 条该补测试还是改措辞

先查它到底差多少。`tests/contract/mock.test.mjs` **已经**支持 `RADIO_BASE_URL` 指到真 server（文件第 2 行就写着这件事），
但同一份文件里有 4 条用例依赖 mock 独有的东西：`/__mock/control`（切 degraded、注入错误码）、`n*` 开头的夹具 id、
以及 `/api/audio/<id>` 那个内存生成的 WAV。真 server 上这三样都不存在（真 server 的媒体走 302 直连远端，ADR-0018）。

所以「同一份断言两边都跑」要么把 mock 独有的用例拆出去（那就不再是「同一组」），要么给真 server 另写一套只读端点的断言。
两个都不便宜 —— 而真 server 的那批端点**已经有** `tests/core/radio.test.mjs` 的 8 条覆盖（HTTP + WS + 媒体 + 令牌 + 降级推断），
只是它不叫「契约测试」，也没和 mock 那份共用断言。

**取舍**：改措辞，把这句话写成事实（「同一份契约，两份夹具」），并点明 mock 独有的控制面为什么过不去。
理由和铁律 5 那条一样：**给文档加功能比改文档贵，而且这里真正缺的不是一次测试，是一句诚实的描述**。
真要收口成「一份断言两个目标」，得先把 mock 独有的控制面从契约面里拆出来 —— 那是 v2 的事，到时要开 ADR。

### 决策

- 四条都**只改文档**（外加 CI 里一条和现实对不上的注释）。不为了坐实这句话去加 ESLint、补测试。
- 顺手把铁律 4 里两条指向**仓库外**的路径（`.scratch/ref.html`、`docs/reference/`）改成找得到的说法：
  前者本来就被 gitignore，后者是别人画面、本来就不入库。文档指向的东西，读者得真能打开。
- 第 4 条是同一类账：**描述计划的段落，计划变了它不会自己变**。一并改成事实，并写明被哪条决定推翻。
- journal 补这一节：把「我们声称的」和「我们做到的」之间的差记在案。这是这个项目最该被看见的部分。
- **不补造小节**：journal 有 3.1、3.8 起的小节，3.2–3.7（PR #12–#17）没有独立小节 —— 铁律 1 只要求 PR 正文四段，
  那六条都写了。事后按结果编一节「当时的困难」，不如留着这个缺口诚实。

### 验证

四件套全绿（`npm run boundaries` / `npm run typecheck` / `npm test` / `npm run build`）。
口播与主题无关这条重新截图核了一遍：light 主题下打开口播，头部与正文跟 dark 一致（`.oa-head` 写死深色，不读 token）。
## 附记 · 真 key 到手，第一件事就踩了两个坑

用户随后给出了他自己那把钥匙与 base url（阿里云百炼的 token-plan 端点）。之前所有「未做」的真 key 冒烟，
这一节补上了 —— 而拿起真 key 的第一个动作，就暴露出两个坑。

### 坑 1 · 带点的 key 被悄悄切了一半

`tools/smoke-llm.mjs` 从文件里抽 key 用的是 `sk-[A-Za-z0-9_-]{8,}` —— **点不在字符集里**。
而百炼 token-plan 的 key 长这样：`sk-sp-<a>.<b>.<c>.<一长串>`。于是它返回了后半截（115 个字符只剩 95 个），
拿半截 key 去打接口，回来的错误看着像「key 无效」—— 一个会让人去查控制台、查权限、查余额的**假故障**。

**怎么发现的**：没等它报错，先量了一下两种规则在这份 key 上各拿到什么：旧规则 95 个字符、新规则整条 115 个。
这个动作只花一分钟，比事后从 401 里往回倒推便宜得多。教训：**启发式抽取必须能被断言**。

**修法**：把抽取从脚本里拿出来，变成纯函数 `tools/key-file.mjs` + `tests/tools/key-file.test.mjs`（5 条断言，
其中一条直接钉住「旧的规则确实只拿到一段」）。规则也改准了：整份内容没有空白就当作 key 本身（不管什么形状），
有空白才按形状找；找不到就返回空串让调用方**明确失败** —— 不许再交出一个被切过的字符串。

### 坑 2 · 公开仓库里躺着作者的桌面路径

同一个函数里的默认值写死成作者本机的桌面路径。功能上无害，但它把作者的 Windows 用户名
带进了一个要给陌生人看的仓库（困难 1 讲的就是同一类事）。改成不给默认值：不给 `--key-file` 就用
`LLM_API_KEY` 环境变量，两个都没有就明确说「没有拿到 key」，而不是去猜一个本机路径。

### 验证

真补全跑通（`npm run smoke:llm -- --key-file=<路径> --base-url=<端点> --model=qwen3.8-max`）：

```
→ openai · https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1 · qwen3.8-max · key sk-…(115)
✓ 工具轨迹：recent_plays → recommend_tracks
✓ say:
    Rain out, so we stay warm and slow.
    You cut the last one off. Heard you, different room now.
    Marina Vale opens it, and nothing here hurries.
✓ play: Cassette Weather — Marina Vale | Half a Morning — Ivo Sand | Harbour Lights — Kite & Ash | Slow Static — Marina Vale | Neon Hours — Kite & Ash
✓ reason: They skipped The Long Way a minute ago, so I dropped that artist entirely and built a hand-picked
  instrumental arc from rain-warm tape tones to a faint evening glow.
✓ segue: Let the tape hiss carry the rain straight into the next one.
```

这一段值得看两眼：脑子的**工具循环**真转起来了（先 `recent_plays` 看历史，再 `recommend_tracks` 找歌），
而且它**读懂了历史里那条 skip**（"You cut the last one off"），把那两个艺人整个剔掉 ——
这是「它不是在自言自语」最直接的证据。4.2 / 4.5 两节里写的「真 key 冒烟：未做」在当时是真的，这里补上了。

key 落在**本机库**（走 `radio.saveSettings` 的写路径，回显里只有 `apiKeySet: true`），没有进仓库。

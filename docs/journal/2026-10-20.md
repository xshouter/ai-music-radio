## 困难 1 · 私人笔记已经躺进公开仓库

**发生了什么**：仓库创建后 `visibility` 是 `PUBLIC`，而 `main` 里带着一份私人笔记 `参考源.md`。
它链向本地知识库的其他笔记（简历准备、另一个项目 nanobot），等于连私人目录结构一起公开了。
发现时它已公开约一天。

**为什么会发生**：建仓库时默认选了 public，**在第一次 push 之前没有清点"这个仓库里到底装了什么"**。
一个只服务作者自己的项目，"公开"这件事本身就没有被当成一次需要评审的变更。

**代价（说清楚，不遮掩）**：旧提交 `6397c5c` 在 GitHub 侧仍可能被按 SHA 访问，直到平台回收不可达对象为止。
强推只能保证它不再出现在任何分支的历史里，不能保证它立刻从平台上消失。

**怎么处理**：
- 改写 root commit，把 `参考源.md` 从历史里彻底移除（`6397c5c` → `10142af`），强推 `main`。
- 重建分支提交（`0290953` → `a7340a0`），保证 PR 的 diff 只包含该有的文件。
- 私人笔记的**公开替代品**写成 `docs/references.md`：只保留公开可说的部分（原型链接、行为观察），
  去掉一切本地路径与内部链接。

**沉淀成规则**：项目文档一律按"要给陌生人看"的尺度写；私人笔记永不入库。

## 困难 2 · 强推基线把 PR 弄坏了

**发生了什么**：为了让 PR 的历史干净，先强推了 `main`（基线），再强推分支。
结果 GitHub 把 PR 钉在旧的 head SHA 上，`mergeable` 一直是 `UNKNOWN`，重开也失败
（`Could not open the pull request`），只能关掉旧 PR 另开一个（PR #2）。

**教训**：改写历史的操作顺序应当是——**先改写远端基线，再让 PR 在干净基线上重新生成**；
更要紧的是：如果一个仓库有开着的 PR，就别在它脚下动基线。
这也是「历史里不该有私人文件」这件事必须**在第一个 PR 之前**处理掉的原因。

## 困难 3 · `.gitignore` 缺一条规则，差点把机器本地文件提交上去

**发生了什么**：`git add -A` 时把 `.codegraph/.gitignore` 加进了提交。
根因是 `main` 的 `.gitignore` 里**没有** `.codegraph/` 这条规则——那条规则只存在于另一个分支的提交里，
于是根目录的忽略规则不生效，而 `.codegraph/.gitignore` 自己的 `*` 规则只挡住了同目录的数据库。

**怎么修**：把 `.codegraph/`、`data/`、`cache/`、`docs/reference/`、`.scratch/` 一次性写进根 `.gitignore`，
从提交里剔除误入文件，并验证 `git check-ignore -v` 的判定符合预期。

## 困难 4 · 规则的机械检查必须先于代码存在

**发生了什么**：铁律 5 要求 CI 能抓 `renderer/` 越界，但此刻仓库里一行代码都没有，
写一个"等有代码再说"的 CI 等于没有 CI；而先上分支保护又会让所有 PR 卡在"等待状态检查"。

**怎么修**：

- 用**故障注入**证明它真的会红：临时造 3 个违规文件，脚本报出 8 处违规并退出码 1，删掉后恢复绿灯。
- 分支保护推迟到本 PR 合并之后再开（否则 PR 自己会被"等待状态检查"锁死）。

## 困难 5 · 第一次 CI 跑了 4 分钟才被领走

**发生了什么**：workflow 文件推上去之后，`gh run list` 一直是空的——GitHub 没有为那次 push 生成任何 run。
补一个空提交重新触发，run 才出现，但 `queued` 持续了约 4 分钟才被 runner 领走（同一账号后续的 run 只需 7 秒）。

**当时的判断**：这是新账号首次注册 workflow 的冷启动，不是配置错误。为了不让它卡住地基合并，
先在本地用故障注入证明脚本会红，然后合并；等 CI 真的跑绿之后才开分支保护，避免 PR 卡在"等待状态检查"。

**沉淀成经验**：新增 workflow 的 PR，第一次 push 未必触发 run——**要显式再推一次来确认它被识别**，别假定它在跑。

## 困难 6 · 我自己编了一条需求，还把它写成了 ADR

**发生了什么**：ADR-0002 与 ADR-0003 的整个讨论都建立在「这个电台会同时有 PC 和手机两个客户端」上。
这个前提**从没有人提过**。它是从原型 UI 的两种形态（宽窗大钟态 / 窄窗卡片态）想象出来的，
而我甚至给这份想象配了一个听起来很正当的理由——"`lan` 是真实的第二个实现"。

**代价**：多写了一个端口、一个目录、一个接口、一个设置项，外加两条不必要的 ADR，
还顺手发明了一个"多端同时出声要不要选主"的问题。真正贵的是它暴露的东西：
**铁律 2 在"我自己想出来的需求"上最容易被绕过**——因为这类需求感觉上不需要问任何人。

**怎么纠正**：ADR-0007 取代 ADR-0002、撤回 ADR-0003；把用词从"两端"改成"两态"，
免得这个词继续鼓励多端的想象；并连带发现一件以前没说清的事——声音是在渲染进程里真正响的，
所以新增 `POST /api/playback`，让 `PlayEvent` 从"server 的预测"变成"渲染进程回报的事实"。

**沉淀成规则**：写 ADR 时，凡是引入**新端口或新实体**的理由，必须能指向一次真实的用户表述或一次真实使用；
指不出来，就不做。

## 阶段 2 · 契约与 mock（同日）

**做了什么**：把第 5 节契约冻成可编译的类型（`shared/domain.ts` + `shared/api-types.ts`），写了一个零依赖假后端
`mock/server.mjs`（含手写 WS 握手、Range、可控的降级 / 错误态），以及契约测试 `tests/contract/mock.test.mjs`；
CI 补上 typecheck 与 test。

**决策：mock 用内建 `http` 而不是 Express。** 抽象层第 7 节写的是「一个 ~100 行的 Express」，
但需求写死了「零依赖（Node 内建 `http`）」。代价是 WS 得手写握手与帧编码，于是 mock 比 100 行长。
这是**为了不带依赖而付的税**，记在这里，免得以后有人把它当过度设计。

**决策：降级与错误的开关放 `/__mock/control`，不进契约。** 验收标准要的是「UI 不需要改一行代码就能显示对应状态」，
所以这个开关不能是契约的一部分——它必须是 UI 永远不会调用的东西。冷启动也可以用
`MOCK_DEGRADED=1` / `MOCK_ERROR=...`。

**决策：`shared/` 的分工。** `domain.ts` 放领域名词，`api-types.ts` 放第 5 节的 DTO 并从 `domain.ts` `import type`。
只有被用到两次以上的联合类型才提升成名字（`DjState` 提了，`DjRole` 没提）。

### 困难 1 · 契约测试抓出的第一个真 bug：mock 会把上一轮的口播推给新客户端

WS 测试要求「连上先拿到 now/queue/plan 快照，之后 chat 的 `say` 逐句推」。第一次跑，`says[0].index`
是 2 而不是 0。根因不在测试：`speak()` 用的是全局 `broadcast`，而 `say` 是靠 `setTimeout` 一句一句推的；
**上一个测试触发的 chat 还剩两句没推完，新客户端正好在这期间连上来，于是收到了一段它从没点过的口播。**
改成「只发给这一轮开始时已在线的客户端」。这正是契约测试该干的事：把一条时间上的耦合逼出来。

### 困难 2 · 测试进程挂住不退

同一个测试的另一半：断言一失败，`socket.destroy()` 就没被执行到，socket 泄漏，
`server.close()` 于是一直等下去，进程永不退出。改在 `t.after()` 里销毁。
教训：**测试里开的长连接，销毁要放在「失败也会执行」的地方。**

### 困难 3 · 服务端把 101 和第一批帧写在同一个 TCP 段里

`http.request` 的 `upgrade` 事件除了 `socket` 还会给一个 `head`——那是握手之后**已经被读进来的字节**。
一开始只用了 `socket`，于是快照帧全部丢掉（并连带造成困难 2）。协议没问题，是客户端实现漏了一个参数。

### 困难 4 · 未知路由该回哪个错误码

契约里的错误码是**封闭枚举**，里面没有 `NOT_FOUND`。所以未知路由只能借用 `INTERNAL`，
但 HTTP 状态码仍该如实回 404。第一版让 `sendError` 直接用错误码自带的 500，测试立刻抓到。
已在 `sendError` 上加 `status` 覆盖位。

### 困难 5 · 本机工具链的绕路（环境注记）

`apply_patch` 走不通——命令经 `cmd` 传递时会在第一个换行处被截断，多行补丁传不过去；`Remove-Item` 被策略直接拦下。
最后的路子是：写文件用 PowerShell 的**单引号 here-string** 配 `[IO.File]::WriteAllText` + `UTF8Encoding($false)`（无 BOM）；
删临时文件用 `node` 的 `fs.rmSync`；读文件用 `node` 打印（node 的 stdout 是 UTF-8，中文正确；PowerShell 的 stdout 不是）。

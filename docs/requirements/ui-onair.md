## 目标

给主界面补上**第二块界面**：DJ 开口时的全屏口播卡。

- 它和主界面一样，是**参考源那张 616×876 卡片的 1:1 复刻** —— 我们的基准画布就是它的尺寸，
  所以参考源的 CSS 数值可以**直接照抄**，不需要换算。
- 它承担本项目最贵的那口 taste：真波形 + 逐词高亮跟随音频。这块是「和参考分不出来」的关键。
- 内容是一段**对当前这首歌的简短分析**（用户定），不是泛泛的问候。

界面上一切数据来自后端（HTTP + WS），一行都不碰数据库（铁律 5）。

## 入口与出口

```
主界面 ──点 DJ 消息下的 PLAY / REPLAY ──▶ 口播全屏态 ──点右上角 ✕ ──▶ 主界面
```

- `PLAY` / `REPLAY` 只出现在**有口播的** DJ 消息上（`meta.turns` 非空）。
- 两者当前行为一致（都是从第一句播起），因为关掉口播就重置了。**这是待确认 2。**
- `✕` 用自绘图标（`Icon` 的 `close`），不用 unicode 的 `✕` —— 它在 Windows 会掉进 emoji 字体。

## 口播时钟：谁在说话

逐词高亮的时间基准是**这一句的 `<audio>`**（`currentTime`），词区间由后端给的
`SpokenWord.startMs/endMs` 决定（ADR-0012）。所以：

- mock 的静音 WAV **按这一句的词时间戳长度生成**（`silentWav(seconds)`）——高亮和音频同源，
  否则真 TTS 接上后会出现「词走完了音频还在放」。
- 整段口播的总长 = 各句末词 `endMs` 之和；进度条 = `已播毫秒 / 总长`。
- 换句 = 换 `<audio>` 的 `src`，`ended` 时进下一句。

## 用户答复（3 条已定案）

1. **口播态不跟主题变** —— 永远是「深头白身」（照参考卡）。DARK / LIGHT 下口播态长得一样。
2. **`PLAY` 与 `REPLAY` 都从头播** —— 两者行为一致，不做「接着上次位置」。
3. **「文字渐隐」指的是按钮上的小字看不清** —— 根因不是渐变，是**字体用错**：所有小标签
   （`LOGIN`/`HIDE`/`FAV`/`PLAY`/`REPLAY`/`QUEUE`/`3 TRACKS`…）原来都写 `var(--dot)` = **Doto**；
   点阵字体在 9–10px 下被抗锯齿糊成虚线。参考源其实只把 Doto 给 wordmark 与大钟，小字用 **Space Grotesk**。
   已修：新增 `--label` 变量 + 内置 `space-grotesk-latin.woff2`（OFL），21 个选择器 `var(--dot)` → `var(--label)`。
## 已知不做（说清楚，别让它变成隐形债务）

- 头部的波形是**程序化**的（参考源也是：静止时走程序化柱状，播放时才叠实时频谱）。
  真频谱要等真 TTS 有声音可分析（阶段 4），那时把 `<audio>` 接进 `AnalyserNode`。
- 不做口播历史列表（属于 3.10 Profile）。
- 不做语速 / 音色控制（属于阶段 4 的 TTS 管道）。

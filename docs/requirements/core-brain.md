# 需求：大脑（`core/brain/`，阶段 4.2）

> 铁律 2 的产出。这份文件回答"大脑到底被要求做什么"，**不回答**"怎么实现"（那在 ADR-0015）。

## 目标

一次推理产出一个电台时段（`Show`）：**一段口播 + 一批歌 + 一句给自己的理由 + 一句可选的过渡**。
它必须是一个**会拒绝**的东西：宁可拒绝定稿，也不许推荐一首不存在的歌。

## 输入（`BrainInput`）

| 字段 | 说明 |
|---|---|
| `trigger` | `schedule` / `chat` / `track_end` / `manual` —— 同一套脑子，四种被叫醒的方式 |
| `userText` | 只有 `chat` 有；对应 UI 的聊天输入框 |
| `now` | 由调用方注入（`Clock`），**大脑自己不取当前时间** |

## 工具契约（封闭，四个）

| 工具 | 入参 | 返回 | 为什么需要它 |
|---|---|---|---|
| `recommend_tracks` | `genres?` `mood?` `limit?` | `{tracks: TrackRef[]}` | "按场景要一批歌" |
| `search_tracks` | `keywords` `limit?` | `{tracks: TrackRef[]}` | 用户点名了歌手/歌名/年代 |
| `recent_plays` | `limit?` | `{plays: {...}[]}` | **避免重复、避开刚被跳过的歌** |
| `emit_show` | `say[]` `play[]` `reason` `segue?` | ——（结束这一轮） | 唯一出口 |

`limit` 越界按 [1, 10]（`recent_plays` 是 [1, 30]）夹住，非法值回默认 —— 与 ADR-0013 同一套"不新增错误码"的处理。

## 定稿校验（硬规则）

1. `say` ≥ 1 句（空的驳回）；最多取 4 句。
2. `reason` 非空。
3. `play` 里的**每个 id 必须是本轮某次工具真的返回过的**，否则整条驳回。
4. `play` 取 3–6 首；一首都没给时从本轮取到过的候选里补足（**不许凭空造**）。
5. 驳回时把**具体理由**当 tool 结果送回模型，让它自己修 —— 这一步是自愈的唯一入口。

## 口播的说话规矩（写进 system prompt，不做成配置）

- **英文**（用户定的口播语言）；平实、口语、低调。
- 1–3 句，每句 18 词以内；不用 emoji / 感叹号 / 电台腔。
- 不许自称 AI/模型；不许提工具、JSON、id、"队列"。
- 用户打字了就**先回答他**，再谈音乐。
- 不念歌单：一个名字足够，且要在该出现的时候出现。

## 默认值（已经定了，不再问）

| 项 | 值 | 依据 |
|---|---|---|
| 步数预算 | 6，最后一步强制 `emit_show` | ADR-0015 |
| 温度 | 未设置（用厂商默认） | 口播要稳，不要惊喜 |
| 默认模型 | `qwen-plus` @ 百炼 compatible-mode | 阶段 4 的现状（其它 key 只改设置） |
| 上下文 | taste 语料（每条截 600 字）+ 最近 10 条播放 + 当天的 plan + 天气 | 见 `core/prompt.ts` |

## 明确写下来的假设

- **假设 1**：`taste.md` 是人写的，长度不由我们控制 → 每条截 600 字，不设上限就等于让一次编辑吃掉 token 预算。
- **假设 2**：播放史是**事实**不是预测（`PlayEvent`），所以"刚被跳过"可以被明确看见，而不是靠猜。
- **假设 3**：天气/日表/语料**任一读不到**都不许让电台开不了口 → 四路各自降级（`gather()` 里的 `catch`）。
- **假设 4**：不用工具的模型存在 → 正文里的 JSON 也认，但走**同一套**校验（不另开一条宽松路径）。
- **假设 5**：v1 不做语音输入（用户定的），所以 `chat` 只来自文字。

## 明确不做

- 不让大脑直接写 `Store`（写入端只有 server 一处，否则统计立刻不可信）。
- 不做多轮"人格记忆"（`taste_updates` 是结构化记录，v1 只写不读回 prompt）。
- 不做推理过程中的取消（`BrainInput` 里没有 `signal`）—— 记在 ADR-0015 的已知限制里。

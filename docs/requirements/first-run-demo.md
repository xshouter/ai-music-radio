# 需求：首次体验（随包的一首歌 + 一段冻结的口播）（PR #61）

> 铁律 2 的产出。这份文件回答「这一轮被要求做成什么」，**不回答**「怎么实现」（那在 ADR-0033）。
> 来源：用户原话「把这首歌放进本地曲库，为它生成一段口播，他们两个都封进包里，作为用户首次进入，
> 没有填写 apikey 和网易云音乐 cookie 时的首次体验」；追加「这首歌的口播就用现在的声音生成一份，固定下来」。

## 摸底：没 key 的人今天看到什么

1. **今天真的是黑屏无声**：`thinkOrStep` 见 `llm.apiKey === ''` → 报 `NO_LLM_KEY`、走 `stepLocally()`，
   而 `userData\music` 是空的 → 队列空、没有歌、没有口播。一条红横幅 + 一块空界面。
   这偏偏是**别人下载 exe 之后的第一印象** —— 这一轮要换掉的就是它。
2. **本地曲库就是 `userData\music`**（`main/main.ts` 的 `localDir`）。本地源按 `Artist - Title.mp3` 猜歌手 / 标题
   （`core/music/local.ts`），而且在降级链的**最后一环** —— 对没 cookie 的人来说，它恰好是唯一的源。
3. **口播是内容寻址缓存**：`core/tts.ts` 落在 `cache/<key>.<ext>`，命中就不调 provider。
4. **「现在的声音」是 `en_GB-alan-medium`**：DB 的 prefs 里没有 `tts.*`（走的是出厂默认），
   而 ADR-0022 追记二把出厂嗓定成了它（95 Hz 中位基频 —— 用户否掉过一把更高的）。
   所以「用现在的声音」= 用 piper + `en_GB-alan-medium` 合成这一份。
5. **打包只认 `extraResources`**：`electron-builder.yml` 已有三条（ui / piper / netease），加一条就够。

## 行为（冻结）

1. **触发**：开机时 `llm.apiKey === ''` → 走首次体验。填上 key 之后**立刻**回正常电台（排表 + 开场口播）。
2. **形态**：和正常开机一模一样 —— 队列里就是那一首、`now` 是它、口播一条 `intro`，自动进口播界面。
   不做欢迎页、不加第二个界面。
3. **嗓子是冻的**：这一段音频是**出厂时用出厂嗓合成的文件**，随包发；用户之后换什么嗓子（包括 fish）
   都不影响它。理由：这条路要的是「没 key 也能出声」，不能反过来依赖任何 key。
4. **歌进本地曲库**：首次开机把随包的那一首拷进 `userData\music`（已存在就不动）；文件名带
   `Artist - Title`，本地源才认得出它。
5. **不设黑名单**：demo 曲就是本地曲库里的一首普通歌 —— 搜得到、播得到、能点红心。
   它不会污染画像，靠的不是排除，而是降级链的顺序：口味画像读的是链上**第一个非空曲库**
   （`core/music/index.ts` 的 `firstNonEmpty`），有 cookie 时读的是他自己的网易云歌单，
   随包那一首在本地目录里、不在那一份里；日表同理 —— 它由大脑排（日推 + 搜索），本地曲库不是它的来源。
   边角：他的网易云歌单一首都没有时，画像会退到读本地目录，那一首会跟着被读到 —— 可接受，它确实在他曲库里。
6. **引导条**：`NO_LLM_KEY` 不再是红色警告 + DISMISS，而是「填入 key / cookie 解锁你自己的电台」的入口，
   点一下打开现有 LOGIN 弹窗（`Credentials`）。文案英文。
7. **失败不阻塞**：demo 的东西缺了（没打进包 / 曲库里找不到）只记一条 warn，界面照常起；
   原来的红色降级路径保持不变。
8. **不动的**：播放器、口播界面、队列、日表、taste、ADR-0029 的流水线一律不动。

# 需求：UI 复刻 · Profile（阶段 3.11）

> 铁律 2 的产物。状态：**已定案**。
> 与凭证弹窗同一情形：用户已授权全托管（「不用停下来问我，你一直往下做」），所以需求由 agent 自己收敛，
> 并把每条假设**显式写下来** —— 铁律 2 的本意是「不留隐含假设」，不是「必须找人问」。
> 上游依据：`docs/requirements/ui-player.md` 交互决策 8（日表的去处）、ADR-0013（新契约）、
> ADR-0004（taste 结构化）、ADR-0010（播放权威在客户端）、ADR-0009（不做歌词）。

## 背景：Profile 是「三件无处可放的东西」的家

到 3.8 为止，主界面已经装下了 Player / QUEUE / DJ 详情 / 口播全屏态。剩下的三样**一直没有界面**：

| 东西 | 为什么没地方放 |
|---|---|
| 收听统计（`PlayStats`） | 参考画面里没有它的位置，3.1 就不猜一个界面出来 |
| 口播 / 聊天历史（`DjMessage[]`） | 同上；且它和 DJ 面板里的聊天不是一件事（那个是当下这一轮） |
| 日表（`DayPlan`） | 交互决策 8 明确不放进 Player，去处写在这里 |

## 入口（这一版定的）

**DjCard 页脚 → Profile**。页脚现在是一行签名 `EDGERUNNER × TASTE.MD`，右边加一个 `PROFILE →` 按钮。

两级关系说得通：DjCard 回答「**你是谁**」（脸、口号、署名、曲风胶囊），Profile 回答「**你听了什么、你的 taste 长什么样**」。
所以不另开顶栏按钮 —— 顶栏已经有 `LOGIN` 和主题切换，再加一个入口只会让那一行变挤。

## 布局规格（自上而下）

```
┌ Profile ────────────────────────────────────┐  ← 与 DJ 详情同源：点阵底纹 + radial glow + --radius
│ (脸 62)  EdgeRunner            [✕]          │  头部固定
│          一开机我就打碟                       │
├─────────────────────────────────────────────┤
│ TASTE                                       │  ← .pf-head：小标签，accent，0.24em 字距
│   LIKES.MD      Warm synth, quiet vocals…   │  语料：文件名（小标签）+ 原文（12px）
│   DISLIKES.MD   No talk radio energy…       │
│   LEARNED       Prefers ambient over…       │  学到的：只给一句话 + HH:MM
├─────────────────────────────────────────────┤
│ TODAY                                       │  日表：3 段
│   07:00–12:00  MORNING   [acoustic][jazz]   │
│     Half a Morning — Ivo Sand …             │
├─────────────────────────────────────────────┤
│ STATS                                       │  四格数字 + Top 艺人
│   PLAYED 12   SKIPPED 3   REPLAYS 6         │
│   TOP      The Long Way ×6                  │
├─────────────────────────────────────────────┤
│ HISTORY                                     │  最近消息，倒序，HH:MM
│   DJ   14:32  Midnight Drive — The Long Way │
├─────────────────────────────────────────────┤
│                                     [CLOSE] │  页脚固定
└─────────────────────────────────────────────┘
```

- 卡片 `max-height: 100%`，**头部与页脚固定、中间滚动**（与 DJ 面板的 `feed-list` 同一套做法）。
- 中间高度不够时不缩字号、不折行挤 —— 滚动。
- 复用既有 token，不引入字面色值；小标签一律 `--label`，名字/时间戳用 `--dot`（点阵只给数字与短名）。

## 决策（已定）

| # | 问题 | 结论 | 理由 |
|---|---|---|---|
| 1 | 入口放哪 | DjCard 页脚 → Profile | 两级「你是谁 / 你听了什么」；顶栏已经够挤 |
| 2 | 空态怎么办 | 每块**各自**给一句空态文案（`Nothing learned yet` / `No plays yet today` / `No messages yet`） | 「没数据」和「坏了」要分得开；错误由统一横幅管 |
| 3 | 统计的时间口径 | `GET /api/stats`（省略 `since` = 今天 00:00），标题写 `TODAY` | 口径写在界面上，别让人猜 |
| 4 | 日表怎么显示 | 每段一行时段 + mood + 曲风胶囊 + 曲目（`title — artist`） | 与 QUEUE 的曲目写法一致，不再发明第三种 |
| 5 | 历史显示几条 | `limit=8`，倒序 | 这是「回看」，不是日志 |
| 6 | 怎么关 | `✕` / `CLOSE` / 点空白 / `Esc` | 与 DjCard、凭证弹窗一致 |
| 7 | 加载态 | 打开时并发打三个接口，未回之前该块显示 `—` | 不做骨架屏：三块都很短，闪一下比骨架更安静 |

## 假设（显式写下来）

- **不做**「清除历史」：契约里没有 delete 语义，需要时再开 ADR。
- **不做**统计图表（折线 / 环形）：参考源里一个图都没有，凭空发明一种视觉语言会破坏它的 taste。
- Profile 里的曲目**可以点**（复用 `onPlay`）：点了就切歌、Profile 留着不关 —— 和 QUEUE 的行为一致。
- 日表**不可编辑**：`POST /api/plan/regenerate` 留给调度器与将来的 UI，这一版只读。

## 验收标准

- [ ] DjCard 页脚能打开 Profile；`✕` / `CLOSE` / 点空白 / `Esc` 都能关
- [ ] 三块数据都来自接口（taste / plan 复用旧端点，stats / history 用 ADR-0013 的新端点），**没有一个数字是写死的**
- [ ] 三块各自的空态都能看到（mock 把历史清空 / 统计归零时可以验）
- [ ] `PLAYSTATS` 的四个数字与 `GET /api/stats` 完全一致，不做前端二次加工
- [ ] DARK / LIGHT 两个主题都正常
- [ ] 中间滚动、头部页脚固定；窗口缩放到最小时布局不折
- [ ] 边界检查通过（`renderer/` 里不许出现凭据 / SQL / `node:*`）

## 已知不做

- 不做分享 / 导出（只服务一个人）。
- 不做「按艺人下钻」到单曲列表（ADR-0013 的「重新打开的条件」）。

# 需求（草稿 · 待确认）· 现场日志：双击之后出了什么事，事后要能读出来

- **状态**：**待确认** —— 第 4 节的假设不反对就按它做，然后冻结、写代码（铁律 2）
- **来源**：用户 2026-10-21 的口头要求（「你做一个方便你查问题的日志功能」），以及第 48 条那次实测的教训
- **关联**：`main/log.ts`（新）、`main/main.ts`、`main/bootstrap.ts`、`main/netease-service.ts`；
  ADR-0034（为什么需要它）、ADR-0035（这一轮的决策）

## 1. 现状（事实）

- 界面上能看到的只有**最后一条**错误的 code + message。历史、上下文、以及「它到底往哪儿发了请求」都不在。
- `main/` 的 `console.warn` / `console.error` 是唯一的过程记录 —— 便携版是**双击启动**的，
  **没有人看得见 stderr**。开发态终端里那几行，发布出去之后全部消失。
- 第 48 条那次「打开没有音乐」：真正花时间的不是修，是**重建现场** —— 数落点里的文件、
  把 prefs 从 sqlite 里读出来、再拿 key 分别打两个域名。这些事本该看一眼日志就完。
- 现有的唯一抓手是 `%APPDATA%\EdgeRunner\` 下的 sqlite：它只有**结果**（消息、播放、日表），没有**过程**。

## 2. 要什么

1. 双击 exe 之后发生的任何事，**事后**能在一个文件里按时间顺序读出来。
2. 读的人不需要懂内部结构：每一次对外请求、每一条错误、开机的每一步，都按同一套格式排着。
3. **不含任何凭证**：随手把它转给别人也不泄露 —— 这是它敢被发出去的前提。
4. 常驻应用，体积不能无限涨。

## 3. 设计

- **落点**：`%APPDATA%\EdgeRunner\logs\edgerunner.log`（`app.getPath('userData')` 下，
  和库 / 曲库同处一个「用户数据」概念里）。
- **格式**：一行一条事件 —— `<ISO 时间>  <区域>  <正文>`。人类可读，前缀稳定（grep 与解析都不难），
  多行正文（上游那一整页 HTML 报错）压成一行再截断。
- **记什么**（每一类都对应一次真实卡过的故障）：

  | 区域 | 内容 | 它治过的病 |
  |---|---|---|
  | `boot` | 开头一行：版本、用户数据路径、**设置摘要**（key / cookie 只记 set / 空）；开机每一步 | 第 48 条：先得知道它带了哪些设置、走到哪一步 |
  | `http` | 每一次对外请求：方法、**去敏后的 URL**、状态码、耗时；非 2xx 带上响应体开头 | 401 到底是哪一路报的、上游原话是什么 |
  | `error` | 每一条流错误，**与界面上看到的一字不差**（code + message） | 界面只留最后一条，历史得能回头看 |
  | `warn` | `core/` 与 `main/` 现有的一切 warn | 「源不可达 / 回落到本地 / 内置服务没起来」这类只在 stderr 说过的话 |
  | `music` | 队列规模、切歌、口播（含音频 URL）；播放回报 | 「没有声音」「不切歌」这类 |

- **去敏是结构性的，不靠猜 key 的形状**：
  - 请求头**一律不记** —— key / cookie 都在头里，不记头就没有它们；
  - URL 里 `cookie / token / key / api_key / sign / session / password` 这类 query 值换成 `<redacted>`；
  - 设置摘要只记「set / 空」，长度都不记。
- **体积**：单文件上限 1 MB；超了就改名成 `edgerunner.log.1`（只留一代）再开新的。
- **实现位置**：`main/`（它知道路径，也是唯一允许用 `node:fs` 的层）。`core/` **一个字不改**：
  出网全部经过 `HttpFetch`，在 `main/` 包一层就等于全记上；`core/` 继续只用它的 `warn` 说话。

## 4. 假设（不反对就按这个做）

| # | 假设 | 理由 |
|---|---|---|
| 1 | 只做**文件**，不做界面上的日志面板 | 用户的原话是「方便**你**查问题」；面板是另一件事，值得单独一轮 |
| 2 | 不做等级开关（debug / info / warn），全记 | 常驻的个人应用，量本来就小；多一个开关就多一条「为什么没记下来」的错路 |
| 3 | 轮转只留一代 | 1 MB 够覆盖最近若干次开机；更久的事，价值低于它的维护成本 |
| 4 | 不把日志暴露成 HTTP 接口 | 那要动契约与令牌；文件已经够用，而且**应用退出之后它还在** |
| 5 | 不记请求体 | LLM 的请求体可能很大；「用了哪个模型 / 哪个地址」由 `boot` 那行设置摘要负责 |
| 6 | 顺手让「内置服务跑着跑着死了」也说话 | 现在只有启动失败会 warn，中途死掉是静默的 —— 而那正是最需要留话的一种（ADR-0028 的进程边界） |

## 5. 验收

- 双击 0.1.7 的 exe、什么都不填 → 日志里看得到 demo 那一轮的每一步，且全文搜不到任何 key / cookie 的形状。
- 填一把**错的** key → 那次请求的状态码与上游原话都在，**但 key 本身不在**。
- 连开十次 → `edgerunner.log` 不超过 1 MB + 一代备份。
- 把日志整个发给别人 → 里面没有任何凭证。

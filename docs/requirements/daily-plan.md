# 需求：日表从日推来（`core/plan.ts` + 大脑的「排表那一轮」）

> 铁律 2 的产出。这份文件回答「日推这件事被要求做成什么」，**不回答**「怎么实现」（那在
> ADR-0030）。来源是用户待办：**「llm 可以根据网易云音乐的每日推荐歌单来生成歌单吗」**。

## 摸底：这不是「接一个新接口」

`netease.recommend` 早就会打 `/recommend/songs`（就是日推）—— 但**只有场景词为空时**才走；
有场景词它走 `/cloudsearch`。而 `buildDayPlan` 每一格都带着 `genres + mood` 去要歌，
于是每一格都落在搜索上：**日推从来没进过日表**。

所以这一轮的题面是「日表从哪儿取料、谁来挑」，不是「多接一个上游」。

## grill 记录（Q/A，原样）

| # | 问题 | 答复 |
|---|---|---|
| Q1 | 日推是**歌单本身**，还是**素材**？ | **(b) 当候选池** —— LLM 来挑、来排序、来分配到时段 |
| Q2 | 三个时段还留吗？ | **留**，三格不动，由 LLM 往三格里分配 |
| Q3 | 日推拿不到怎么办？ | **退到现有做法**：按场景词每格搜 3 首 |
| Q4 | 喂什么上下文？ | **taste 画像 + 最近真实播放史（跳过 / 重听）+ 现在几点、今天几号** |
| Q5 | 只能从日推里挑，还是允许自己搜？ | **能从日推，也允许自己搜** |

**Q5 的推论（决定了实现形状）**：排表那一轮**必须是能调工具的一轮**，不能是一次裸 completion。
裸 completion 里模型没法「搜一下再决定」，而 Q5 明确允许它自己搜。所以这一轮**复用
`ToolLoopBrain` 的工具环**，只是换一个终局工具 —— 不新写第二条编排。

## 行为（冻结）

1. **同一套工具环，换一个终局**：排表那一轮的工具集是
   `PLAN_TOOLS = daily_recommend + search_tracks + recent_plays + emit_plan`。
   播歌那一轮的 `TOOLS` **一个字都不动**（它是「放歌」这件事的全部）。
2. **`daily_recommend` = 空场景词的 `music.recommend({}, limit)`**。它语义上就是日推那一条路
   （netease 源：无场景词 → `/recommend/songs`（要登录）→ 退 `/personalized/newsong`）。
   模型先叫它拿到候选，才能选。
3. **`emit_plan` 收 `blocks: string[][]`**：**按槽位顺序**，一格一个 id 数组。
   id 必须是本轮某次工具真的返回过的 —— 与 `emit_show` 同一条铁律（不许编 id）。
4. **校验是宽松的**：日表是草图，**不照搬** `emit_show` 的 `MIN_TRACKS = 3`；一格空着不算坏。
   比给的槽多的块**忽略**（三格是产品的脾气，不是模型的输入）。
5. **任何一步失败都不许把电台停掉**：某一格没歌 / 整轮排表失败 / 模型吐了坏 JSON →
   那一格（或整份）**退到现有搜索**（Q3）。这与 ADR-0024「排不出来不是错误」是同一条。
6. **一天只排一次**不变（ADR-0024）：重启复用同一份，`regeneratePlan` 走同一条路。
7. **没配 LLM key 时不发那一轮**：直接走搜索兜底 —— 白等一轮没有意义。

## 不做

- 不改 `PlanBlock` / `DayPlan` 契约（UI、库表、mock 都不动）。
- 不新增 `trigger`：`plan()` 自带提示词，不靠 `trigger` 分派（沿用 `schedule`）。
- 不动 `netease.recommend` 的两级退让（ADR-0016 的既定取舍）。
- **UI 无改动**：日表本来就是 `plan` 事件 + `/api/plan/today`。铁律 3（先前端再后端）在这一轮
  没有前端面 —— 记下来，免得下次误以为漏了。

## 验收

- 单测 `tests/core/brain.test.mjs`：`PLAN_TOOLS` 的名字数组；`plan()` 的 happy path、
  编造 id 被驳回并自愈、槽位缺块（第 3 格空着不塌进前一格）。
- 单测 `tests/core/plan.test.mjs`：curate 给了就用；缺格退搜索；curate 抛错退搜索；
  没有 curate 就是原来的三格搜索。
- 集成 `tests/core/radio.test.mjs`：boot 的第一条音乐请求是 `/recommend/songs`，
  且它**早于** `/cloudsearch` —— 证明日表确实从日推取料。

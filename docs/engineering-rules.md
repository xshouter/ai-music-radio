# 工程铁律（细则）

> 五条铁律的正文在 `AGENTS.md`。这份文件写「怎么落地」和「怎么被发现违反」。

---

## 铁律 1 · 代码用 git 管理

**要求**
- `main` 是保护分支：禁止直接 push，必须走 PR，且 CI 绿灯才能合并。
- 分支命名：`feat/…`、`fix/…`、`docs/…`、`chore/…`。
- 合并方式：squash merge，保持 `main` 上一条 PR 一个提交。
- 提交信息：`type(scope): 一句话`，正文写「为什么」而不是「改了什么」。
- **一个 PR 只做一件事**，且必须能被单独读懂、单独回滚。

**PR 正文强制四段**（模板见 `.github/pull_request_template.md`）
1. **背景** —— 要解决什么，为什么现在做。
2. **遇到的困难** —— 卡在哪、试过什么、为什么失败。**没有困难就写"无"，但不许空着。**
3. **决策与取舍** —— 选了 A 没选 B，代价是什么。架构级决策同时开 ADR。
4. **验证证据** —— 测试输出、截图、手工验收步骤与结果。不许只写"已验证"。

**被违反的样子**：直接把改动推到 `main`；PR 只有一句"改了一下"；先合再补文档。

## 铁律 2 · 需求必须 grill

**要求**
- 任何需求在写第一行代码前，必须被**逐轮追问**到没有隐含假设。
- grill 以「轮次」进行：每轮问当前"前沿"的问题（前置条件已定的问题），给出推荐答案，等回答再问下一轮。
- grill 的产出落盘：`docs/requirements/<feature>.md`，含**决策树**、已定结论、以及**明确写下来的假设**。
- 没有 `docs/requirements/<feature>.md` 的需求，不进开发。

**何时可以停**：前沿为空——每个分叉都被走过，没有"默认这么干"的沉默假设。

**被违反的样子**：拿到一句话需求就开始写；把"我猜用户想要 X"写进代码而不是写进文档。

## 铁律 3 · 先前端再后端

**要求**
- 顺序固定：**冻结 API 契约 → 写 mock → 做界面 → 换真后端**。详见 `docs/abstraction-layer.md` 第 7 节。
- 契约进 `shared/api-types.ts`，是前后端唯一真相；改契约要开 ADR。
- 界面必须在**只有 mock** 的情况下能跑通全部状态，包括空态、加载态、以及抽象层第 6 节列出的**全部降级/错误态**。
- 后端实现完成后，UI **一行不改**即可切换（只换 base URL）。任何"接真后端时改了 UI"都是契约没冻结的信号。

**被违反的样子**：先写数据库和 API 再考虑界面；界面里为了迁就后端临时字段而写特判。

## 铁律 4 · 样式不明确就要截图

**要求**

遇到以下任何一项，**停下来向用户要参考截图**，不要猜：
- 颜色（背景、边框、强调色、状态色）
- 间距/尺寸/圆角/阴影
- 字体、字号层级、字重
- 动效（时长、缓动、出现方式）
- 空态、错误态、加载态、禁用态的视觉
- 图标风格、封面比例、波形样式

**怎么要**：说清**具体是哪个界面、哪个元素、不确定的是哪一项**，并给出 2–3 个我倾向的选项，让用户用一张截图定掉。

**例外**：能从已有参考截图（`docs/reference/`）直接读出来的，不用问。

**被违反的样子**：自己挑一个颜色就写进去；做出"差不多像"但和参考对不上的界面。

## 铁律 5 · 前端永远不碰数据库

**要求**
- 渲染进程与后端之间**只有** HTTP + WS（`docs/abstraction-layer.md` 第 5 节）。
- `renderer/` 里**禁止** import：`better-sqlite3`、`sqlite3`、`electron`、`node:fs`、`node:path`、`node:child_process`、`core/**`、`main/**`。
- `renderer/` 里**禁止**出现：SQL 字符串、数据库文件路径、任何 API key 的明文读写逻辑。
- 数据库只属于 `core/state/`，且只通过 `Store` 端口被访问。

**机械检查**（两道，CI 上都跑）
1. ESLint `no-restricted-imports` + `import/no-restricted-paths`，按 `docs/abstraction-layer.md` 第 2 节的依赖表配置，`renderer/` 违规即 error。
2. CI 里一条脚本：扫 `renderer/**` 是否出现 `sqlite`/`better-sqlite3`/`SELECT `/`INSERT ` 等特征串。

**被违反的样子**：为了"性能"让前端直连库；把 key 存在前端 localStorage 再由前端调第三方 API。

## 违反铁律怎么办

- CI 能抓的（铁律 1 / 5）→ 直接红，改到绿为止。
- CI 抓不到的（铁律 2 / 3 / 4）→ 在 PR 自查清单里逐条勾选；review 时按四段正文倒查。
- 已合入的违规：开一个 `fix/` PR 修掉，并在 `docs/journal/` 里记一笔"怎么违规的、怎么防住的"。
